1(a) Underfitting, overfitting and the bias–variance tradeoff

fundamentals
QuestionExplain underfitting, overfitting, and Bias-Variance tradeoff.

Underfitting occurs when a model is too simple to represent the underlying relationship. It has high bias and usually high training and validation error.

Overfitting occurs when the model fits the training examples and their noise too closely. It has very low training error but high validation/test error, and therefore high variance.

The bias–variance tradeoff means choosing enough model complexity to capture the true pattern without fitting noise:

\[ \boxed{ \text{Too simple} \rightarrow \text{high bias} } \qquad \boxed{ \text{Too complex} \rightarrow \text{high variance} } \]
Training errorValidation errorDiagnosis
Underfittinghighhighhigh bias
Overfittinglowhighhigh variance
Good fitlowlowbalanced

1(b) The perceptron learning rule and its parameters

perceptron
QuestionDescribe the task of a perceptron learning rule. Suppose we have the following perceptron and corresponding learning algorithm. Explain the factors and parameters of the above learning (training) approach.

A perceptron performs binary classification by computing a weighted sum of the inputs

\[ z = w^{T}x + b \]

and applying a threshold function to decide the predicted class.

During training an error \(e\) is computed between the target and the prediction. If the example is misclassified, the weights are updated by the perceptron learning rule:

\[ \boxed{ w_i \leftarrow w_i + \alpha\,x_i\,e } \qquad\text{and typically}\qquad b \leftarrow b + \alpha e \]
SymbolMeaning
\(x_i\)the \(i\)-th input feature
\(w_i\)the weight on that input
\(b\)the bias, shifting the decision boundary
\(e\)the prediction error (target − output)
\(\alpha\)the learning rate, controlling step size

Training repeats over multiple epochs until the errors disappear or a stopping condition is reached.

Note the structure of the rule: the update is proportional to both the input and the error, so a large input with a large error produces a large correction, while a correctly classified example (\(e=0\)) produces no change at all.

1(c) What features a network learns on handwritten digits

representation learning
QuestionThe figure shows examples of handwritten digits. What features might you expect a good NN to learn when trained with data like this? Explain the process in neural networks of how features are fed in the input layer and how the hidden layer performs the intermediate operation.

A neural network would first learn simple features such as horizontal and vertical strokes, edges, curves, corners and loops. Deeper hidden layers combine these into digit-specific structures — closed loops in \(0,6,8,9\), a single vertical stroke in \(1\), intersections and curves elsewhere.

How the information flows

The input layer receives pixel intensities. Each hidden neuron computes

\[ z = w^{T}x + b \]

followed by a nonlinear activation. Successive layers combine lower-level patterns into increasingly abstract features, until the output layer produces probabilities over the digit classes.

  pixels ──► strokes / edges ──► curves, loops, junctions ──► digit shapes ──► class
   input        hidden 1              hidden 2                 hidden 3      output

  each neuron:   z = wᵀx + b   then   a = g(z)

The nonlinearity is essential: without \(g(\cdot)\), stacked layers would collapse into a single linear map and the network could never build the hierarchy described above.

2(a) Classification vs object detection vs instance segmentation

vision tasks

TaskOutputSeparates instances?
Classificationone class label for the whole image—
Object detectionclass labels + bounding boxesyes, by box

Classification assigns a single label to the entire image. Object detection identifies individual objects and predicts both their class and their bounding box. Instance segmentation performs detection together with a pixel-level mask for every object, so separate instances of the same class can be distinguished.

2(b) Solving overlapping detections

NMS
QuestionWhich approach is used by object detectors to solve overlapping detections?

Object detectors commonly use Non-Max Suppression (NMS).

The highest-confidence box is selected first and kept. Other boxes whose IoU overlap with that box exceeds a threshold are suppressed. The process repeats until only the strongest non-redundant detections remain.

\[ \text{suppress if } \; IoU \ge T_{NMS} \]

With multiple classes, NMS runs independently per class — a car box should not suppress an overlapping person box.

2(c)(i) How mean Average Precision is calculated

detection metrics
QuestionExplain how the Mean Average Precision (mAP) is calculated.
  1. For each object class, sort the predicted detections by confidence.
  2. Using an IoU threshold, label each prediction a true positive or false positive.
  3. Compute precision and recall across confidence thresholds to build the precision–recall curve.
  4. The area under that curve gives the Average Precision (AP) for that class.
  5. Average the AP over all classes.
\[ \boxed{ mAP = \frac{1}{C}\sum_{c=1}^{C} AP_c } \]

where \(C\) is the number of classes. Results are often reported at a single IoU threshold (e.g. mAP@0.5) or averaged over several thresholds.

3(a) Advantages of convolutional over fully connected layers

CNN design
QuestionWhat are the advantages of using convolutional layers instead of fully connected ones for visual tasks?

Convolutional layers exploit local spatial relationships in images through small receptive fields, and reuse the same filters across all locations through weight sharing.

This gives far fewer parameters than fully connected layers, improved computational efficiency, reduced overfitting, and the ability to learn hierarchical visual features — edges, then textures, then parts, then objects.

PropertyFully connectedConvolutional
Connectivityevery input to every neuronlocal receptive field
Weightsunique per connectionshared across positions
Parameter countvery largesmall
Spatial structuredestroyed by flatteningpreserved

3(b) Mathematical reasoning for 1×1 dimension reduction

Inception
QuestionWhat is the mathematical reasoning behind using \(1\times1\) convolutions as dimension reduction layers before larger convolutions (\(3\times3,5\times5\)) in the Inception module, and how does this affect the computational complexity?

Suppose a feature map has \(C_{in}\) channels and a large \(K\times K\) convolution produces \(C_{out}\) channels. Its approximate cost is

\[ HW\,C_{in}C_{out}K^{2} \]

If a \(1\times1\) convolution first reduces the channels from \(C_{in}\) to \(C_r\), the total cost becomes

\[ HW\big(C_{in}C_r\big) \;+\; HW\big(K^{2}C_rC_{out}\big) \]

Since \(C_r \ll C_{in}\), the expensive \(K\times K\) convolution now operates on far fewer channels. The \(1\times1\) layer therefore acts as an inexpensive bottleneck, substantially reducing both computation and parameters.

Worked numbers

With \(H=W=28\), \(C_{in}=192\), \(C_r=16\), \(C_{out}=32\), \(K=5\):

PathMACs
Direct \(5\times5\), \(192\rightarrow32\)120,422,400
\(1\times1\), \(192\rightarrow16\)2,408,448
then \(5\times5\), \(16\rightarrow32\)10,035,200
Bottleneck total12,443,648
\[ \approx \boxed{9.7\times \text{ cheaper}} \]

The saving comes from the \(K^{2}C_{in}\) term: the \(5\times5\) kernel now spans 16 channels instead of 192.

3(c) What adding x to F(x) achieves

ResNet
QuestionWhat happens when we add the input \(x\) directly to the output of convolution layers \((F(x)+x)\), and why is this better than just stacking layers?

This forms a residual (skip) connection:

\[ \boxed{ y = F(x) + x } \]

Instead of learning the full mapping, the convolutional block only needs to learn the residual correction \(F(x)\).

          ┌──────────── identity shortcut ────────────┐
          │                                           ▼
   x ─────┴──► [ conv → ReLU → conv ] ──► F(x) ──►   (+)  ──► y = F(x) + x

The shortcut lets information and gradients flow directly across the block, making very deep networks easier to optimise. If the additional layers are unnecessary, the block can learn \(F(x)\approx0\), giving approximately the identity mapping \(y\approx x\) — which a stack of plain nonlinear layers finds surprisingly hard to reproduce. This is the central idea of ResNet.

3(d) How EfficientNet balances size against accuracy

EfficientNet
QuestionHow does EfficientNet balance the tradeoff between model size and accuracy?

EfficientNet uses compound scaling. Instead of scaling only depth, only width or only image resolution, it increases all three in a coordinated way:

\[ \boxed{ \text{Depth} + \text{Width} + \text{Resolution} } \]

scaled together according to a fixed computational budget. This gives a better accuracy–efficiency balance than arbitrarily making a network only deeper or only wider.

Scale only…Becomes the bottleneck
Depthtoo little detail and too few feature types to work with
Widthtoo shallow to combine features into high-level structure
Resolutionreceptive field too small to cover the larger image

4(a) The primary disadvantage of R-CNN

detectors
QuestionWhat is the primary disadvantage of the Region-based CNN (R-CNN)?

R-CNN is computationally expensive. It first generates many region proposals, then runs the CNN separately on each proposal.

Because proposals overlap heavily, the same image regions are processed repeatedly, making both training and inference slow. It also uses a multi-stage pipeline — proposals, CNN features, SVM classification, box regression — rather than a single end-to-end trainable detector.

4(b) Faster R-CNN step by step, by stage

two-stage detection
QuestionDescribe step-by-step how Faster R-CNN processes an input image to produce final object detections. In your explanation, identify which steps belong to the first stage and which belong to the second stage.

Shared backbone

The input image is passed through a CNN backbone to obtain a convolutional feature map, which both stages share.

Stage 1 — Region Proposal Network (RPN)

  1. The RPN slides over the shared feature map.
  2. It predicts objectness scores and bounding-box offsets for a set of anchors.
  3. High-quality proposals are retained, usually after an NMS step.

Stage 2 — Detection head

  1. Features for each proposal are extracted from the shared map using ROI pooling / ROI align.
  2. The detection head predicts the final object class.
  3. It further refines the bounding-box coordinates.
  4. A final NMS produces the output detections.
   image ──► CNN backbone ──► shared feature map
                                    │
                    ┌───────────────┴───────────────┐
              STAGE 1: RPN                    STAGE 2: head
          anchors → objectness            ROI pool → class
          + box offsets → proposals       + box refinement
                    └───────────────┬───────────────┘
                                    ▼
                              NMS ──► final detections
\[ \boxed{ \text{Faster R-CNN is a two-stage detector: propose, then classify and refine.} } \]

4(c) One-stage vs two-stage detectors

detector comparison

The fundamental difference is that one-stage detectors perform detection directly in a single prediction pipeline, whereas two-stage detectors first generate candidate regions and then perform detailed classification and regression on those regions.

The extra stage is exactly where the accuracy comes from and exactly where the time goes — which is why the trade-off is so consistent.

5(a) What GANs are

GAN
QuestionWhat are Generative Adversarial Networks (GANs)?

A GAN is a generative framework containing two neural networks trained against each other:

NetworkRole
Generator \(G\)transforms random noise into synthetic samples
Discriminator \(D\)tries to determine whether a sample is real or generated

The two are trained adversarially: the generator becomes better at producing realistic samples while the discriminator becomes better at distinguishing them. Neither improves in isolation — each one's progress creates the training signal for the other.

5(b) Why the generator’s cost opposes the discriminator’s

GAN
QuestionExplain why the cost function of the generator is the opposite of the discriminator.

The two networks have directly opposing objectives. The discriminator tries to correctly distinguish real from fake samples; the generator tries to make fake samples indistinguishable from real ones.

So if the discriminator minimises its classification error on generated samples, the generator must move its parameters in the opposite direction — it succeeds precisely when the discriminator fails. This adversarial relationship is expressed by the minimax objective:

\[ \boxed{ \min_G \max_D V(D,G) } \]

Note the single shared value function \(V\): one network maximises it while the other minimises it, which is what makes the two costs exact opposites rather than merely different.

5(c) What happens when the discriminator becomes too strong

GAN training
QuestionWhat happens when the discriminator becomes too strong during GAN training?

If the discriminator becomes nearly perfect very early, it can trivially separate fake samples from real ones.

The generator then receives extremely weak or uninformative gradients — when \(D(G(z))\approx0\), the term \(\log(1-D(G(z)))\) is flat, so there is almost no signal telling the generator how to improve. Training becomes unstable or stalls entirely.

\[ \boxed{ \text{GAN training requires a balance between } G \text{ and } D \text{ learning.} } \]

This is the vanishing-gradient problem in a different costume: the loss saturates, and a saturated loss carries no information.

6(a) Why Transformers use multi-head attention

Transformer
QuestionWhy does the Transformer use Multi-Head Attention instead of single-head attention, and how does this help capture different types of relationships in the data?

A single attention head learns one set of query–key–value relationships. Multi-head attention runs several in parallel:

\[ head_i = \text{Attention}\big(QW_i^{Q},\,KW_i^{K},\,VW_i^{V}\big) \]

Different heads can attend to different relationships at the same time — local dependencies, long-range relationships, syntactic structure, or distinct semantic patterns. Their outputs are concatenated and projected:

\[ \boxed{ \text{MultiHead}(Q,K,V) = \text{Concat}(head_1,\ldots,head_h)\,W^{O} } \]

Multi-head attention therefore gives the model several complementary representation subspaces, rather than forcing one attention mechanism to capture every kind of relationship at once.

6(c) Purpose of each LSTM component

LSTM
QuestionFor each component you drew in part (b), explain its purpose and how it processes information.

The forget gate determines how much of the previous memory \(C_{t-1}\) is retained:

\[ f_t = \sigma(\cdots) \]

The input gate determines how much new candidate information is written, and the candidate supplies the content itself:

\[ i_t = \sigma(\cdots), \qquad \tilde C_t = \tanh(\cdots) \]

The cell state is then updated by

\[ \boxed{ C_t = f_t\odot C_{t-1} + i_t\odot\tilde C_t } \]

The output gate \(o_t=\sigma(\cdots)\) determines how much of the current memory is exposed as the hidden state:

\[ \boxed{ h_t = o_t\odot\tanh(C_t) } \]
ComponentActivationRangeRole
Forget gate \(f_t\)\(\sigma\)(0,1)how much old memory survives
Input gate \(i_t\)\(\sigma\)(0,1)how much new content is written
Candidate \(\tilde C_t\)\(\tanh\)(−1,1)what the new content is
Output gate \(o_t\)\(\sigma\)(0,1)how much memory is exposed

Sigmoid gates produce values between 0 and 1 and therefore behave like soft switches, while tanh produces candidate values between \(-1\) and \(1\) — content that can be positive or negative.

7(a) How seq2seq encoder–decoder processes sequences

seq2seq
QuestionIn basic sequence-to-sequence (seq2seq) models with RNNs, explain how the encoder-decoder architecture processes the input sequence and generates the output sequence.

The encoder RNN reads the input sequence \(x_1,x_2,\ldots,x_T\) one element at a time, continually updating its hidden state. In the basic architecture, the encoder's final hidden state is used as a fixed-size context vector representing the entire input.

The decoder RNN receives this context vector and generates output tokens sequentially, \(y_1,y_2,\ldots,y_{T'}\). Each generated token and the decoder's previous hidden state influence the next output.

   x₁ → x₂ → x₃ → ... → x_T
    │    │    │          │
   [encoder RNN]─────────► c  (final hidden state = context vector)
                          │
                          ▼
                    [decoder RNN] → y₁ → y₂ → ... → y_T'

7(b) The fixed-size context vector limitation

seq2seq
QuestionIdentify the key limitation when using a fixed-size context vector for long sequences in a seq2seq model with RNNs.

The entire input sequence must be compressed into one fixed-size vector, creating an information bottleneck.

For long sequences the context vector cannot preserve all the important information, and what is lost first tends to be information from early input positions — those have been overwritten by many subsequent updates. Decoder performance therefore deteriorates as sequence length increases.

   x₁ x₂ x₃ x₄ ... x₅₀  ──────► [ c ]  ← one vector, fixed size
   ↑                                      regardless of whether T = 5 or 500
   this end fades first

7(c) How attention fixes the bottleneck

attention
QuestionHow does the attention mechanism address these limitations? (i) Describe how attention modifies the basic seq2seq architecture. (ii) Explain how the context vector is computed differently with attention.

(i) The architectural change

With attention, the encoder retains the hidden state at every input position \(h_1,h_2,\ldots,h_T\), instead of forcing all information into only the final hidden state.

(ii) How the context vector is computed

At decoder step \(t\), an attention score \(e_{t,i}\) is calculated between the decoder state and every encoder hidden state. The scores are normalised by softmax:

\[ \alpha_{t,i} = \frac{e^{e_{t,i}}}{\sum_j e^{e_{t,j}}} \]

and the context vector becomes a weighted sum of all encoder states:

\[ \boxed{ c_t = \sum_i \alpha_{t,i}\,h_i } \]
   h₁   h₂   h₃   h₄   ...   h_T        encoder states, all kept
    │    │    │    │          │
   α₁   α₂   α₃   α₄   ...   α_T        weights, recomputed each step
    └────┴────┴────┴──────────┘
                 ▼
                c_t  ──► decoder step t

The crucial difference: the context vector is different at every decoder step. The decoder can dynamically focus on whichever input positions are most relevant to the token currently being generated, largely eliminating the fixed-vector bottleneck.

\[ \text{basic seq2seq: one } c \text{ for the whole output} \qquad \text{with attention: a new } c_t \text{ per output token} \]
