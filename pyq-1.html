1(a) Gradient descent in backpropagation5 marks

chain rule → gradient → step downhill
QuestionDescribe briefly how gradient descent is used to find the optimal weights in the backpropagation algorithm. Mention a problem that may arise from using gradient descent.

In a neural network, the objective of training is to find weights and biases that minimise the cost or loss function \(J\). During backpropagation, the chain rule is used to compute the gradient of the loss with respect to every trainable parameter:

\[ \frac{\partial J}{\partial w} \]

The gradient indicates the direction in which the loss increases most rapidly. Gradient descent therefore changes the weight in the opposite direction:

\[ \boxed{ w^{new}=w^{old}-\alpha\frac{\partial J}{\partial w} } \]

where \(\alpha\) is the learning rate. The training sequence is:

\[ \boxed{ \text{Forward pass} \rightarrow \text{Compute loss} \rightarrow \text{Backpropagate gradients} \rightarrow \text{Update weights} \rightarrow \text{Repeat} } \]

Geometrically, gradient descent moves downhill on the loss surface toward a minimum:

  J
  ^
  │  ●  start
  │   ╲
  │    ●
  │     ╲
  │      ●
  │       ╲___●___
  │              ‾‾●‾‾        each step:  w ← w − α ∂J/∂w
  └──────────────────────► w
                 minimum

The problem

The neural-network loss surface is generally non-convex. Gradient descent is therefore not guaranteed to reach the global minimum — it may settle in local minima, stall at saddle points, or crawl across flat regions. Poor learning-rate selection can also make convergence very slow or unstable.

1(b) Effect of the learning rate5 marks

step size — speed vs stability
QuestionIn the backpropagation algorithm, the learning rate parameter \(\alpha\) controls the amount of change of a weight in each iteration. What happens if the learning rate is too high? What happens if it is too low?

The learning rate \(\alpha\) determines the step size of the gradient-descent update:

\[ w^{new}=w^{old}-\alpha\frac{\partial J}{\partial w} \]

If \(\alpha\) is too large, each update may move too far. The optimisation can repeatedly overshoot the minimum, causing the loss to oscillate; in the extreme case the loss increases continuously and training diverges.

If \(\alpha\) is too small, the updates are safe but tiny, so training converges very slowly and may need a very large number of iterations.

  Too high — overshoots           Good — steady descent          Too low — crawls
  J                               J                              J
  │╲    ╱╲    ╱╲                  │╲                             │╲
  │ ╲  ╱  ╲  ╱  ╲                 │ ╲__                          │ ╲_
  │  ╲╱    ╲╱    ╲                │    ╲____                     │   ╲__
  │                               │         ╲______              │      ╲___
  └──────────────► iter           └──────────────► iter          └──────────────► iter

The learning rate must therefore balance speed against stability:

\[ \boxed{ \alpha \text{ too high} \Rightarrow \text{unstable / overshooting} } \] \[ \boxed{ \alpha \text{ too low} \Rightarrow \text{very slow convergence} } \]

A practical diagnostic: if the loss curve oscillates or rises, reduce \(\alpha\); if it falls smoothly but barely moves, increase it.

1(c) Random search, grid search and coarse-to-fine4 marks

search the dimension that matters
QuestionWhy is random search often better than grid search for hyperparameter tuning? Explain the "coarse-to-fine" strategy of hyperparameter tuning.

In grid search, fixed values are chosen for every hyperparameter and all combinations are evaluated. The problem is that some hyperparameters strongly influence performance while others barely matter — and grid search wastes many experiments re-testing values of the unimportant ones.

Suppose \(x\) is an important hyperparameter and \(y\) is relatively unimportant. With 16 trials each:

   Grid search (16 trials)            Random search (16 trials)

 y │  ×    ×    ×    ×               y │        ×            ×
   │                                   │  ×            ×
   │  ×    ×    ×    ×                 │      ×     ×      ×
   │                                   │            ×          ×
   │  ×    ×    ×    ×                 │   ×     ×      ×    ×
   │                                   │ ×          ×     ×
   │  ×    ×    ×    ×                 │     ×           ×
   └──┴────┴────┴────┴──► x            └─┴──┴─┴──┴─┴─┴──┴─┴─┴─► x

   only 4 distinct values of x        16 distinct values of x
   (the dimension that matters)       explored along x

Grid search tests only four distinct values of the important hyperparameter; random search explores sixteen. Random search therefore covers the useful part of the search space far more efficiently for the same budget.

Coarse-to-fine

In the coarse-to-fine strategy, we first search broadly over a large range. Having identified a promising region, we restrict the range and search it more finely.

\[ \boxed{ \text{Large search space} \rightarrow \text{Find promising region} \rightarrow \text{Search that region more finely} } \]

For example, \(\alpha\in[10^{-5},1]\) may be searched first; if good results cluster around \(10^{-3}\), a second finer search concentrates near that region.

3(a) Universal Approximation Theorem4 marks

existence, not learnability
QuestionState the Universal Approximation Theorem. Does this theorem imply that shallow neural networks are always preferable to deep networks? Justify your answer.

The Universal Approximation Theorem states that a feedforward neural network with at least one hidden layer, sufficiently many hidden neurons and a suitable nonlinear activation function can approximate any continuous function on a compact domain to arbitrary accuracy.

Formally, for a target continuous function \(f(x)\) and any desired error \(\epsilon>0\), there exists a network \(\hat f(x)\) such that

\[ \boxed{ |f(x)-\hat f(x)|<\epsilon } \]

over the specified domain.

  y
  │            ___
  │        ___╱   ╲___          ——— target f(x)
  │    ___╱            ╲__      - - - network f̂(x)
  │ - - - - - - - - - - - -
  │        everywhere within ε
  └──────────────────────────► x

Does it favour shallow networks?

No. The theorem only guarantees that an approximating shallow network exists. It does not state:

  • how many neurons are required — the number can be astronomically large;
  • whether gradient descent will actually find those weights;
  • whether the resulting network will generalise to unseen data.

A shallow network might need an enormous number of neurons, whereas a deep network can often represent hierarchical and complex functions far more efficiently with fewer parameters. The theorem is a statement about existence, not about learnability, size or generalisation.

3(b) Diagnosing training error 2%, dev error 15%5 marks

large gap ⇒ variance
QuestionA model has Training error = 2% and Dev (validation) error = 15%. Diagnose whether this is high bias or high variance. What are two practical steps you would take to improve the model?

The training error is very low but the validation error is much higher:

\[ E_{train}=2\%, \qquad E_{dev}=15\%, \qquad \text{gap} = 15\%-2\% = 13\% \]

The model performs very well on data it has seen and poorly on unseen data. That large generalisation gap is the signature of

\[ \boxed{ \text{High variance / overfitting} } \]
  Error
   │                            ███████████  Dev = 15%
   │                            ███████████
   │                            ███████████
   │   ██                       ███████████
   │   ██  Train = 2%           ███████████
   └───────────────────────────────────────►
        the gap (13%) is the variance

Two practical steps

  1. Increase regularisation — for example L2 regularisation or dropout — so the network cannot fit the training data excessively.
  2. Increase the effective amount of training data — collect more samples, or apply suitable data augmentation.

Reducing model complexity or applying early stopping would also help. Note what you would not do: making the network bigger addresses high bias, and here bias is clearly not the problem — 2% training error shows the model has ample capacity.

3(c) L2-regularised logistic regression5 marks

penalty on \(\sum w^2\)
QuestionWrite the cost function for L2-regularized logistic regression. Explain how the regularization parameter \(\lambda\) affects training error and model complexity.

For logistic regression the ordinary cross-entropy cost is

\[ -\frac{1}{m}\sum_{i=1}^{m}\Big[ y^{(i)}\log\hat y^{(i)} + (1-y^{(i)})\log(1-\hat y^{(i)}) \Big] \]

With L2 regularisation, a penalty on large weights is added:

\[ \boxed{ J(w,b) = -\frac{1}{m}\sum_{i=1}^{m}\Big[ y^{(i)}\log\hat y^{(i)} + (1-y^{(i)})\log(1-\hat y^{(i)}) \Big] + \frac{\lambda}{2m}\sum_j w_j^{2} } \]

The bias \(b\) is usually not regularised, since it only shifts the decision boundary and does not control model complexity.

Effect of \(\lambda\)

\(\lambda\) controls the strength of the penalty. As \(\lambda\uparrow\), large weights are punished more heavily, so the weights shrink and the model becomes less complex. This reduces variance and overfitting, but training error normally increases — the model is no longer free to fit the training set exactly. If \(\lambda\) becomes excessively large the model becomes too simple and suffers high bias, i.e. underfitting.

\(\lambda\)Model complexityTraining errorRisk
Very smallHighLowOverfitting
ModerateBalancedModerateGood generalisation
Very largeLowHighUnderfitting

Read the table downwards: training error moves in one direction only. It is the validation error that is U-shaped, and the best \(\lambda\) sits at the bottom of that U.

5(a) Regularization and three techniques4 marks

L2 · dropout · augmentation
QuestionWhat is regularization? Explain three regularization techniques used in training neural networks.

Regularisation refers to techniques used to reduce overfitting and improve a network's ability to generalise to unseen data. Rather than letting the network memorise the training set perfectly, regularisation constrains or perturbs the learning process so the model learns more general patterns.

1. L2 regularisation

A penalty proportional to the square of the weights is added to the cost:

\[ J_{reg} = J + \frac{\lambda}{2m}\sum w^{2} \]

This discourages extremely large weights and generally produces a smoother, less complex model.

2. Dropout

During training, neurons are randomly switched off with a specified probability. The network therefore cannot depend excessively on any particular neuron and is pushed toward robust, distributed representations.

   full network              with dropout (p = 0.5)
     ●   ●   ●                  ●   ✕   ●
      ╲ ╱ ╲ ╱                    ╲     ╱
     ●   ●   ●                  ✕   ●   ●
      ╲ ╱ ╲ ╱                      ╲ ╱
     ●   ●   ●                  ●   ●   ✕      ✕ = dropped this step

3. Data augmentation

Additional training examples are generated by applying label-preserving transformations such as flipping, cropping, rotation or scaling. This increases the effective diversity of the training set and reduces overfitting.

5(b) Deep vs shallow networks and vanishing gradients2 marks

product of many small factors
QuestionWhich type of neural network, deep or shallow, is more prone to the vanishing-gradient problem? Why?
\[ \boxed{ \text{Deep neural networks} } \]

During backpropagation, the gradient for an early layer contains a product of many derivatives:

\[ \frac{\partial L}{\partial W_1} \;\propto\; f'_1 f'_2 f'_3 \cdots f'_L \]

If many of these derivatives have magnitude less than 1, repeated multiplication drives the product toward zero. A deep network contains many more such factors than a shallow one, so its earliest layers may receive almost no useful learning signal and train extremely slowly.

Concretely, with a factor of \(0.25\) per layer, 10 layers already give \(0.25^{10}\approx 10^{-6}\).

5(c) Activation functions prone to vanishing gradients2 marks

saturating activations
QuestionWhich activation functions are prone to the vanishing-gradient problem, and why?
\[ \boxed{ \text{Sigmoid and Tanh} } \]

Both saturate for sufficiently large positive or negative inputs, so their derivatives fall toward zero.

For sigmoid,

\[ \sigma'(z)=\sigma(z)\big(1-\sigma(z)\big), \qquad 0<\sigma'(z)\le 0.25 \]

so the derivative is at most \(0.25\) even at its best, and approaches zero in the saturated regions. For tanh,

\[ \tanh'(z)=1-\tanh^{2}(z) \]

which approaches zero when \(|z|\) is large. Repeated multiplication of these small derivatives through a deep network causes the gradient to vanish.

ActivationDerivativeMaximumSaturates?
Sigmoid\(\sigma(1-\sigma)\)0.25both tails
Tanh\(1-\tanh^2\)1.0both tails
ReLU0 or 11.0negative side only

Tanh is the milder of the two — its derivative can reach 1, whereas sigmoid shrinks the gradient by at least \(4\times\) at every layer even in the best case. ReLU is included for contrast: its derivative is exactly 1 wherever the unit is active, which is why it largely fixed the problem.

5(d) Data augmentation on the test set2 marks

no random augmentation at test
QuestionShould data augmentation be applied to the test set? Explain your reasoning.
\[ \boxed{ \text{No} } \]

Training-style random data augmentation should not be applied to the test set. The purpose of the test set is to give an unbiased estimate of performance on unseen examples; random transformations alter the test distribution and make the evaluation inconsistent and non-reproducible.

However, standard deterministic preprocessing — resizing, normalisation — is still applied, because the network requires inputs in the same format it was trained on.

A special exception is test-time augmentation such as multi-crop testing, where several predefined transformed versions are deliberately evaluated and their predictions combined. That is a controlled, repeatable procedure, not random perturbation.

5(e) Multi-crop testing2 marks

average several fixed crops
QuestionExplain the concept of multi-crop testing and discuss why it is used during model evaluation.

In multi-crop testing, several different crops are extracted from the same test image — for example centre, top-left, top-right, bottom-left and bottom-right — and each is passed separately through the network.

              ┌─ Crop 1 ──► Prediction 1 ┐
              │                           │
  Image ──────┼─ Crop 2 ──► Prediction 2 ┤
              │                           ├──► average scores ──► final prediction
              ├─ Crop 3 ──► Prediction 3 ┤
              │                           │
              └─ Crop 4 ──► Prediction 4 ┘

The class probabilities or logits from the crops are usually averaged to produce the final prediction.

Multi-crop testing reduces sensitivity to the exact position or framing of an object and can improve robustness. The cost is that inference becomes several times more expensive, since the same image is processed multiple times.

5(f) Counting trainable parameters2 marks

watch the off-by-one
QuestionYou'd like to train a fully connected neural network with 5 hidden layers, each with 10 hidden units. The input is 20-dimensional and the output is a scalar. What is the total number of trainable parameters?

For every fully connected layer:

\[ \boxed{ \text{Parameters} = (\text{inputs}\times\text{outputs}) + \text{biases} } \]

The architecture is \(20 \rightarrow 10 \rightarrow 10 \rightarrow 10 \rightarrow 10 \rightarrow 10 \rightarrow 1\).

Input → hidden layer 1

\[ 20(10)+10 = 210 \]

Between the hidden layers

Five hidden layers means four \(10\rightarrow10\) connections:

\[ 4\big[10(10)+10\big] = 4(110) = 440 \]

Final hidden layer → scalar output

\[ 10(1)+1 = 11 \]
\[ N = 210+440+11 \qquad \boxed{ \text{Total trainable parameters} = 661 } \]
ConnectionWeightsBiasesTotal
\(20\rightarrow10\)20010210
\(10\rightarrow10\) (×4)40040440
\(10\rightarrow1\)10111
Total61051661

The classic slip is counting five \(10\rightarrow10\) connections instead of four. Five layers have four gaps between them — the same off-by-one as fenceposts.

7(a) The problem non-max suppression solves2 marks

duplicate boxes for one object
QuestionWhich problem in object detection is addressed by non-max suppression?

An object detector often predicts several highly overlapping bounding boxes for the same physical object. One car might produce five different boxes with slightly different positions and confidence scores. If all are kept, the detector reports the same object multiple times.

Non-Max Suppression (NMS) removes these duplicate detections. It keeps the highest-confidence box and suppresses lower-confidence boxes that overlap it strongly, according to an IoU threshold.

   Before NMS                        After NMS

   ┌──────────┐                      
   │ ┌────────┼──┐                   ┌──────────┐
   │ │  ┌─────┼──┼──┐                │          │
   │ │  │ car │  │  │      ──►       │   car    │
   └─┼──┼─────┘  │  │                │          │
     └──┼────────┘  │                └──────────┘
        └───────────┘
   5 boxes, 1 object                 1 box, 1 object
\[ \boxed{ \text{NMS removes redundant overlapping detections.} } \]

7(b) Multi-class non-max suppression2 marks

run NMS per class
QuestionHow is non-max suppression applied in the presence of multiple object classes?

With multiple classes, NMS must be applied separately to each object class. A car box should compete with other car boxes, but it should not suppress a person box merely because the two overlap — a person standing in front of a car is a perfectly valid pair of detections.

Multi-class NMS algorithm

  1. Generate all predicted bounding boxes with their confidence scores and predicted classes.
  2. Discard boxes whose confidence score is below a chosen confidence threshold.
  3. Separate the remaining boxes by class: cars, persons, motorcycles, …
  4. For each class independently:
    • select the remaining box with the highest confidence;
    • output / keep that box;
    • compute its IoU with all remaining boxes of the same class;
    • remove every box for which \(IoU \ge T_{NMS}\);
    • repeat until no boxes remain in that class.
  5. Combine the surviving detections from all classes to obtain the final prediction set.
            Predicted boxes
                   ↓
          Confidence filtering
                   ↓
            Separate by class
                   ↓
        ┌──────────┼──────────┐
       Car       Person      Bike
        ↓          ↓          ↓
       NMS        NMS        NMS          ← independent, same-class IoU only
        └──────────┼──────────┘
                   ↓
            Final detections

Low-probability boxes are removed first, then NMS runs independently per class. Doing it in that order keeps the per-class loops short.

7(c) When anchor-box detectors perform poorly2 marks

capacity per grid cell is fixed
QuestionUnder which two conditions do anchor-box-based detection frameworks exhibit degraded performance?

In the anchor-box formulation used by YOLO, an object is assigned to the grid cell containing its midpoint, and to the anchor box having the highest IoU with that object's shape. Anchor boxes make it possible to detect multiple overlapping objects in one grid cell, provided they are assigned to different anchors.

Performance therefore degrades in two situations:

  1. Two objects fall in the same grid cell and both best-match the same anchor box. One grid-cell/anchor slot cannot represent two independent objects simultaneously, so one of them is lost.
  2. More objects fall into one grid cell than there are anchor boxes. If a cell has two anchors but three object centres land inside it, there are simply not enough slots to represent all three.
   ┌─────────────┐      2 anchors available in this cell
   │  ●  ●  ●    │      3 object midpoints fall inside
   │             │      →  one object cannot be represented
   └─────────────┘
\[ \boxed{ \text{Anchor boxes help with overlapping objects, but capacity per grid cell is still limited.} } \]

Both failures come from the same root cause: representational capacity is fixed at (grid cells) × (anchors per cell), decided before training. Finer grids or more anchors relieve it, but never remove it.
