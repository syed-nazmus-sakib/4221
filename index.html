Part I — Backpropagation Practice Set

Three fully worked three-layer networks: forward pass, loss, and backward pass with δ signals.

Notation Used in All Problems

The same symbols are used throughout. All vectors are column vectors.

  • \((W_1,b_1)\) — first layer  ·  \((W_2,b_2)\) — second layer  ·  \((W_3,b_3)\) — output layer
  • \((z_1,a_1)\) — weighted sum & activation of the first layer
  • \((z_2,a_2)\) — weighted sum & activation of the second layer
  • \((z_3,\hat y)\) — output weighted sum & prediction
  • \((\delta_3,\delta_2,\delta_1)\) — error signals during backpropagation
The forward pass moves \(x\rightarrow a_1\rightarrow a_2\rightarrow\hat y\); the backward pass always runs in reverse \(\delta_3\rightarrow\delta_2\rightarrow\delta_1\).

Problem 1 · \(2\rightarrow2\rightarrow2\rightarrow1\)

ReLU hidden layers + Sigmoid / BCE output.

Given

\[x=\begin{bmatrix}1\\-1\end{bmatrix},\qquad y=1\] \[W_1=\begin{bmatrix}0.5&0.2\\-0.3&0.4\end{bmatrix},\quad b_1=\begin{bmatrix}0.1\\-0.2\end{bmatrix}\] \[W_2=\begin{bmatrix}0.6&-0.5\\0.2&0.3\end{bmatrix},\quad b_2=\begin{bmatrix}0.1\\-0.1\end{bmatrix}\] \[W_3=\begin{bmatrix}0.7&-0.4\end{bmatrix},\quad b_3=0.05\]

Both hidden layers use ReLU; the output uses sigmoid with BCE loss.

Forward propagation

1. First hidden layer

\[z_1=W_1x+b_1,\qquad a_1=\operatorname{ReLU}(z_1)\]

Write the ReLU derivative immediately — \(\operatorname{ReLU}'(z_1)\) is a vector of only \(0\) or \(1\).

2. Second hidden layer

\[z_2=W_2a_1+b_2,\qquad a_2=\operatorname{ReLU}(z_2)\]

Also write \(\operatorname{ReLU}'(z_2)\).

3. Output layer

\[z_3=W_3a_2+b_3,\qquad \hat y=\sigma(z_3),\qquad \sigma(z)=\frac{1}{1+e^{-z}}\]

4. Loss

\[L=-\big[y\ln\hat y+(1-y)\ln(1-\hat y)\big]\]

Since \(y=1\), this simplifies to \(L=-\ln\hat y\).

Backpropagation

5. Output error

Because this is sigmoid with BCE:

\[\boxed{\delta_3=\hat y-y}\]

6. Output-layer gradients

\[dW_3=\delta_3\,a_2^{T},\qquad db_3=\delta_3\]

Dimension \((1\times1)(1\times2)=1\times2\), matching the shape of \(W_3\).

7. Error at the second hidden layer

Carry the output error backward through \(W_3\), then apply the local ReLU derivative:

\[\boxed{\delta_2=(W_3^{T}\delta_3)\odot\operatorname{ReLU}'(z_2)}\]

8. Second-layer gradients

\[dW_2=\delta_2\,a_1^{T},\qquad db_2=\delta_2\]

Dimension \((2\times1)(1\times2)=2\times2\).

9. Error at the first hidden layer

\[\boxed{\delta_1=(W_2^{T}\delta_2)\odot\operatorname{ReLU}'(z_1)}\]

10. First-layer gradients

\[dW_1=\delta_1 x^{T},\qquad db_1=\delta_1\]

Dimension \((2\times1)(1\times2)=2\times2\).

Problem 2 · \(2\rightarrow2\rightarrow1\rightarrow1\)

Sigmoid first hidden layer + ReLU second hidden layer + Sigmoid / MSE output. Mixes scalar and vector backprop.

Given

\[x=\begin{bmatrix}1\\2\end{bmatrix},\qquad y=0\] \[W_1=\begin{bmatrix}0.4&-0.2\\-0.1&0.3\end{bmatrix},\quad b_1=\begin{bmatrix}0.1\\-0.2\end{bmatrix}\] \[W_2=\begin{bmatrix}0.6&-0.4\end{bmatrix},\quad b_2=0.1\] \[W_3=0.8,\quad b_3=-0.1\]

First hidden layer: sigmoid. Second hidden layer: ReLU. Output: sigmoid. Loss: MSE, \(L=\tfrac12(\hat y-y)^2\).

Forward propagation

1. First hidden layer

\[z_1=W_1x+b_1,\qquad a_1=\sigma(z_1)\]

Apply sigmoid to each value separately.

2. Second hidden layer (single neuron → scalar)

\[z_2=W_2a_1+b_2,\qquad a_2=\operatorname{ReLU}(z_2)\]

Write \(\operatorname{ReLU}'(z_2)\) — either \(0\) or \(1\).

3. Output layer

\[z_3=W_3a_2+b_3,\qquad \hat y=\sigma(z_3)\]

4. Loss

\[L=\tfrac12(\hat y-y)^2\]

Since \(y=0\), \(L=\tfrac12\hat y^2\).

Backpropagation

5. Output error

The shortcut \(\delta_3=\hat y-y\) cannot be used alone because the loss is MSE, not BCE. The correct output error is:

\[\boxed{\delta_3=(\hat y-y)\,\hat y(1-\hat y)}\]

6. Output gradients (all scalars)

\[dW_3=\delta_3 a_2,\qquad db_3=\delta_3\]

7. Error at the second hidden layer (scalar)

\[\boxed{\delta_2=W_3\,\delta_3\,\operatorname{ReLU}'(z_2)}\]

8. Second-layer gradients

Although \(\delta_2\) is a scalar, \(W_2\) has two weights:

\[dW_2=\delta_2 a_1^{T},\qquad db_2=\delta_2\]

Dimension \((1\times1)(1\times2)=1\times2\).

9. Error at the first hidden layer

Carry the scalar error backward through \(W_2^{T}\) (giving a \(2\times1\) vector), then apply the sigmoid derivative \(\sigma'(z_1)=a_1\odot(1-a_1)\):

\[\boxed{\delta_1=(W_2^{T}\delta_2)\odot a_1\odot(1-a_1)}\]

10. First-layer gradients

\[dW_1=\delta_1 x^{T},\qquad db_1=\delta_1\]

Problem 3 · \(2\rightarrow2\rightarrow2\rightarrow2\)

ReLU first hidden layer + Sigmoid second hidden layer + Softmax output. Two-class classification.

Given

\[x=\begin{bmatrix}2\\-1\end{bmatrix},\qquad y=\begin{bmatrix}0\\1\end{bmatrix}\] \[W_1=\begin{bmatrix}0.3&0.2\\-0.4&0.5\end{bmatrix},\quad b_1=\begin{bmatrix}0.1\\0.2\end{bmatrix}\] \[W_2=\begin{bmatrix}0.6&-0.3\\0.2&0.4\end{bmatrix},\quad b_2=\begin{bmatrix}0\\0.1\end{bmatrix}\] \[W_3=\begin{bmatrix}0.7&-0.2\\-0.3&0.6\end{bmatrix},\quad b_3=\begin{bmatrix}0.05\\-0.05\end{bmatrix}\]

First hidden layer: ReLU. Second hidden layer: sigmoid. Output: softmax. Loss: categorical cross-entropy.

Forward propagation

1. First hidden layer

\[z_1=W_1x+b_1,\qquad a_1=\operatorname{ReLU}(z_1)\]

Write \(\operatorname{ReLU}'(z_1)\).

2. Second hidden layer

\[z_2=W_2a_1+b_2,\qquad a_2=\sigma(z_2),\qquad \sigma'(z_2)=a_2\odot(1-a_2)\]

3. Output logits

\[z_3=W_3a_2+b_3=\begin{bmatrix}z_{3,1}\\z_{3,2}\end{bmatrix}\]

4. Softmax probabilities

\[\hat y_1=\frac{e^{z_{3,1}}}{e^{z_{3,1}}+e^{z_{3,2}}},\qquad \hat y_2=\frac{e^{z_{3,2}}}{e^{z_{3,1}}+e^{z_{3,2}}}\]

Check: \(\hat y_1+\hat y_2=1\).

5. Loss

Target \(y=[0,1]^{T}\), so the second class is correct and categorical cross-entropy becomes:

\[\boxed{L=-\ln\hat y_2}\]

Backpropagation

6. Output error

For softmax with categorical cross-entropy:

\[\boxed{\delta_3=\hat y-y}=\begin{bmatrix}\hat y_1-0\\\hat y_2-1\end{bmatrix}\]

7. Output-layer gradients

\[dW_3=\delta_3 a_2^{T}\ (2\times2),\qquad db_3=\delta_3\]

8. Error at the second hidden layer

\[\boxed{\delta_2=(W_3^{T}\delta_3)\odot a_2\odot(1-a_2)}\]

9. Second-layer gradients

\[dW_2=\delta_2 a_1^{T},\qquad db_2=\delta_2\]

10. Error at the first hidden layer

\[\boxed{\delta_1=(W_2^{T}\delta_2)\odot\operatorname{ReLU}'(z_1)}\]

11. First-layer gradients

\[dW_1=\delta_1 x^{T},\qquad db_1=\delta_1\]

The General Backprop Pattern

For a three-layer network \(x\rightarrow a_1\rightarrow a_2\rightarrow\hat y\), the backward pass always runs in reverse \(\delta_3\rightarrow\delta_2\rightarrow\delta_1\). At every layer:

Move the error backward

\[\boxed{\text{previous error}=W^{T}(\text{next error})\odot\text{local activation derivative}}\]

Weight gradients

\[\boxed{dW=(\text{current }\delta)\times(\text{previous activation})^{T}}\]

Bias gradients

\[\boxed{db=\text{current }\delta}\]
The one exception to “\(\delta_3=\hat y-y\)” is Problem 2: with MSE + sigmoid you must include the sigmoid derivative, \(\delta_3=(\hat y-y)\hat y(1-\hat y)\). Softmax+CE and sigmoid+BCE both collapse to the clean \(\hat y-y\).

Which Input Each Weight Gradient Uses

The easiest way to avoid confusion — each \(dW\) uses the activation that enters that layer:

\[\boxed{dW_3=\delta_3 a_2^{T}}\qquad\text{because }a_2\text{ enters the output layer}\]
\[\boxed{dW_2=\delta_2 a_1^{T}}\qquad\text{because }a_1\text{ enters the second layer}\]
\[\boxed{dW_1=\delta_1 x^{T}}\qquad\text{because }x\text{ enters the first layer}\]

2 · 2→2→1→1σ, ReLU, σ\((\hat y-y)\hat y(1-\hat y)\) (sigmoid + MSE)

Part II — Final Backpropagation Practice Set

Four architectures from a single sigmoid neuron up to 3→2→2, plus a pattern cheat-sheet.

Notation & Core Rules

Simple notation, all vectors are column vectors:

  • \((W_1,b_1)\) — first layer  ·  \((W_2,b_2)\) — output / second layer
  • \((z_1,a_1)\) — hidden weighted sum & activation
  • \((z_2,\hat y)\) — output weighted sum & prediction
  • \(\delta_2\) — output error  ·  \(\delta_1\) — hidden-layer error
\[\boxed{dW=(\text{current }\delta)\times(\text{previous activation})^{T}}\]
\[\boxed{db=\text{current }\delta}\]
\[\boxed{\text{hidden }\delta=(W_{\text{next}}^{T}\delta_{\text{next}})\odot(\text{activation derivative})}\]

Problem 1 · \(3\rightarrow2\rightarrow1\)

ReLU hidden layer + Sigmoid / BCE output — one of the most likely exam structures.

Given

\[x=\begin{bmatrix}1\\-1\\2\end{bmatrix},\qquad y=1\] \[W_1=\begin{bmatrix}0.4&0.2&-0.1\\-0.3&0.5&0.2\end{bmatrix},\quad b_1=\begin{bmatrix}0.1\\-0.2\end{bmatrix}\] \[W_2=\begin{bmatrix}0.8&-0.5\end{bmatrix},\quad b_2=0.1\]

Hidden layer ReLU, output sigmoid, loss BCE.

Forward propagation

Step 1 — Dimensions

\(x:3\times1\), \(W_1:2\times3\), \(b_1:2\times1\), \(z_1,a_1:2\times1\), \(W_2:1\times2\), \(z_2,\hat y:1\times1\).

Step 2 — First-layer weighted sum

\[z_1=W_1x+b_1\]

Step 3 — Apply ReLU

\[a_1=\operatorname{ReLU}(z_1),\qquad \operatorname{ReLU}(z)=\begin{cases}z,&z>0\\0,&z\le0\end{cases}\]

Immediately write \(\operatorname{ReLU}'(z_1)\) — only zeros and ones.

Step 4 — Output weighted sum

\[z_2=W_2a_1+b_2\quad(\text{scalar})\]

Step 5 — Prediction

\[\hat y=\sigma(z_2),\qquad \sigma(z)=\frac{1}{1+e^{-z}}\]

Step 6 — BCE loss

Because \(y=1\): \(L=-\ln\hat y\).

Backpropagation

Step 7 — Output delta

\[\boxed{\delta_2=\hat y-y}\]

Step 8 — Output-layer gradients

\[\boxed{dW_2=\delta_2 a_1^{T}}\ (1\times2),\qquad \boxed{db_2=\delta_2}\]

Step 9 — Hidden delta

\[\boxed{\delta_1=(W_2^{T}\delta_2)\odot\operatorname{ReLU}'(z_1)}\]

Step 10 — Hidden-layer gradients

\[\boxed{dW_1=\delta_1 x^{T}}\ (2\times3),\qquad \boxed{db_1=\delta_1}\]

Finally, identify any dead hidden neuron — that row of \(dW_1\) becomes zero.

Problem 2 · \(3\rightarrow2\rightarrow2\)

Sigmoid hidden layer + Softmax / Cross-Entropy output — two-class, mutually exclusive.

Given

\[x=\begin{bmatrix}1\\0\\-1\end{bmatrix},\qquad y=\begin{bmatrix}0\\1\end{bmatrix}\] \[W_1=\begin{bmatrix}0.3&-0.2&0.4\\-0.5&0.1&-0.3\end{bmatrix},\quad b_1=\begin{bmatrix}0.1\\0.2\end{bmatrix}\] \[W_2=\begin{bmatrix}0.6&-0.2\\-0.4&0.5\end{bmatrix},\quad b_2=\begin{bmatrix}0.1\\-0.1\end{bmatrix}\]

Hidden layer sigmoid, output softmax, loss categorical cross-entropy.

Forward propagation

Step 1 — Dimensions

\(x:3\times1\), \(W_1:2\times3\), \(b_1,z_1,a_1:2\times1\), \(W_2:2\times2\), \(b_2,z_2,\hat y:2\times1\).

Step 2 — Hidden weighted sum

\[z_1=W_1x+b_1\]

Step 3 — Hidden activation

\[a_1=\begin{bmatrix}\sigma(z_{1,1})\\\sigma(z_{1,2})\end{bmatrix},\qquad \boxed{\sigma'(z_1)=a_1\odot(1-a_1)}\]

Step 4 — Output logits

\[z_2=W_2a_1+b_2=\begin{bmatrix}z_{2,1}\\z_{2,2}\end{bmatrix}\]

Step 5 — Softmax probabilities

\[\hat y_1=\frac{e^{z_{2,1}}}{e^{z_{2,1}}+e^{z_{2,2}}},\qquad \hat y_2=\frac{e^{z_{2,2}}}{e^{z_{2,1}}+e^{z_{2,2}}}\]

Verify \(\hat y_1+\hat y_2=1\).

Step 6 — Cross-entropy loss

Correct class is the second, so \(L=-\ln\hat y_2\).

Backpropagation

Step 7 — Output delta

\[\boxed{\delta_2=\hat y-y}=\begin{bmatrix}\hat y_1\\\hat y_2-1\end{bmatrix}\]

Step 8 — Output-layer gradients

\[\boxed{dW_2=\delta_2 a_1^{T}}=\begin{bmatrix}\delta_{2,1}\\\delta_{2,2}\end{bmatrix}\begin{bmatrix}a_{1,1}&a_{1,2}\end{bmatrix}\ (2\times2),\qquad \boxed{db_2=\delta_2}\]

Step 9 — Hidden delta

\[\boxed{\delta_1=(W_2^{T}\delta_2)\odot a_1\odot(1-a_1)}\]

Step 10 — Hidden-layer gradients

\[\boxed{dW_1=\delta_1 x^{T}}\ (2\times3),\qquad \boxed{db_1=\delta_1}\]

Because \(x_2=0\), the second column of \(dW_1\) must be zero — predict it before multiplying.

Problem 3 · \(1\rightarrow1\rightarrow1\)

ReLU hidden neuron + Sigmoid / BCE output — everything is scalar.

Given

\[x=2,\quad y=0,\quad w_1=0.5,\ b_1=-0.4,\quad w_2=-0.7,\ b_2=0.2\]

Hidden neuron ReLU, output sigmoid + BCE.

Forward propagation

\[z_1=w_1x+b_1,\qquad a_1=\operatorname{ReLU}(z_1)\] \[\operatorname{ReLU}'(z_1)=\begin{cases}1,&z_1>0\\0,&z_1\le0\end{cases}\] \[z_2=w_2a_1+b_2,\qquad \hat y=\sigma(z_2)\]

Because \(y=0\): \(\boxed{L=-\ln(1-\hat y)}\).

Backpropagation

\[\boxed{\delta_2=\hat y-y}=\hat y\quad(\text{since }y=0)\] \[\boxed{dw_2=\delta_2 a_1},\qquad \boxed{db_2=\delta_2}\] \[\boxed{\delta_1=w_2\,\delta_2\,\operatorname{ReLU}'(z_1)}\] \[\boxed{dw_1=\delta_1 x},\qquad \boxed{db_1=\delta_1}\]

Important scalar-chain trick

If \(z_1\le0\) then \(\operatorname{ReLU}'(z_1)=0\), so \(\delta_1=0\) and therefore \(dw_1=0,\ db_1=0\). The output-layer gradients may still be nonzero, but the hidden-neuron gradients vanish.

Extra mini-variation

Change only \(b_1=-1.2\). Don't recompute everything — first determine: is the ReLU active? Is \(\delta_1\) zero? Are \(dw_1\) and \(db_1\) zero?

Problem 4 · \(2\rightarrow1\)

Single sigmoid neuron with BCE loss — no hidden layer.

Given

\[x=\begin{bmatrix}1\\-2\end{bmatrix},\quad y=1,\quad W=\begin{bmatrix}0.6&-0.3\end{bmatrix},\quad b=0.1\]

Sigmoid neuron, BCE loss.

Forward propagation

Dimensions: \(x:2\times1\), \(W:1\times2\), \(b,z,\hat y:1\times1\).

\[z=Wx+b=w_1x_1+w_2x_2+b,\qquad \hat y=\sigma(z)\]

Since \(y=1\): \(\boxed{L=-\ln\hat y}\).

Backpropagation

\[\boxed{\delta=\hat y-y}\] \[\boxed{dW=\delta x^{T}}=\delta\begin{bmatrix}1&-2\end{bmatrix}=\begin{bmatrix}\delta&-2\delta\end{bmatrix},\qquad \boxed{db=\delta}\]

Parameter update

Using \(\eta=0.1\):

\[\boxed{W_{\text{new}}=W-\eta\,dW},\qquad \boxed{b_{\text{new}}=b-\eta\,db}\]

Final Pattern Sheet

\(2\rightarrow1\)

\[z=Wx+b,\quad \hat y=\sigma(z),\quad \delta=\hat y-y,\quad dW=\delta x^{T},\quad db=\delta\]

\(1\rightarrow1\rightarrow1\)

\[z_1=w_1x+b_1,\quad a_1=f(z_1),\quad z_2=w_2a_1+b_2\] \[\delta_2=\text{output error},\quad dw_2=\delta_2 a_1\] \[\delta_1=w_2\delta_2 f'(z_1),\quad dw_1=\delta_1 x\]

\(3\rightarrow2\rightarrow1\)

\[dW_2=\delta_2 a_1^{T},\quad \delta_1=(W_2^{T}\delta_2)\odot f'(z_1),\quad dW_1=\delta_1 x^{T}\]

\(3\rightarrow2\rightarrow2\)

Same formulas, but \(\delta_2\) is now a \(2\times1\) vector:

\[dW_2=\delta_2 a_1^{T}\ \Big[(2\times1)(1\times2)=2\times2\Big],\quad \delta_1=(W_2^{T}\delta_2)\odot f'(z_1),\quad dW_1=\delta_1 x^{T}\]
The only real change between these architectures is the shape of the delta and gradient matrices. The backpropagation logic is identical.

Part III — VGG Architecture

Focus: VGG-16 — the standard model for architecture, output-size, and parameter-count questions.

Overview: VGG-16 Pipeline

Your lecture presents VGG-16 as:

224×224×3 → [Conv 64]×2 → Pool → [Conv 128]×2 → Pool → [Conv 256]×3 → Pool → [Conv 512]×3 → Pool → [Conv 512]×3 → Pool → FC 4096 → FC 4096 → Softmax 1000

Every convolution uses a \(3\times3\) filter, stride \(1\), and same padding. Every pooling layer uses \(2\times2\) max pooling with stride \(2\).

1. Why Was VGG Introduced?

Before VGG, architectures such as AlexNet used different convolution sizes: \(11\times11\), \(5\times5\), \(3\times3\). VGG introduced a much simpler principle:

Build a deep network almost entirely by repeatedly stacking small \(3\times3\) convolutions.

The architecture is therefore deep, uniform, easy to understand, easy to implement, and structurally predictable. The central idea is not a special block like ResNet or Inception. The important idea is:

\[\text{Depth through repeated small convolutions}\]

2. Why Use \(3\times3\) Convolutions?

A \(3\times3\) convolution is the smallest filter that captures spatial relationships in all directions: left/right, above/below, and diagonals. VGG stacks several \(3\times3\) layers instead of using one large convolution.

Two \(3\times3\) convolutions versus one \(5\times5\)

Two consecutive \(3\times3\) convolutions have an effective receptive field of \(5\times5\). Ignoring biases, suppose input and output both have \(C\) channels.

One \(5\times5\) convolution requires \(25C^2\) parameters. Two \(3\times3\) convolutions require:

\[2(9C^2)=18C^2 \quad<\quad 25C^2\]

The two \(3\times3\) layers use \(\dfrac{18}{25}=0.72\) of the parameters of one \(5\times5\) layer — about 28% fewer parameters. They also introduce two nonlinear activation stages instead of one:

Conv → ReLU → Conv → ReLU

This gives the network greater representational power.

Three \(3\times3\) convolutions versus one \(7\times7\)

Three \(3\times3\) layers provide an effective \(7\times7\) receptive field.

  • One \(7\times7\) layer: \(49C^2\) parameters.
  • Three \(3\times3\) layers: \(3(9C^2)=27C^2\) parameters.

Thus stacked \(3\times3\) layers give fewer parameters, more nonlinearities, and deeper feature extraction.

3. Meaning of “VGG-16”

VGG-16 has 16 trainable weight layers:

  • 13 convolution layers,
  • 3 fully connected layers.
\[13+3=16\]

Pooling layers and ReLU activations are not counted because they have no trainable weights. This is a common exam question.

4. VGG-16 Block Structure

VGG-16 consists of five convolution blocks.

Block 1

Input \(224\times224\times3\). Two convolutions \(\text{Conv}3\times3,\ 64\), then \(\text{MaxPool}2\times2,\ s=2\).

Output: \(112\times112\times64\)

Block 2

Input \(112\times112\times64\). Two convolutions \(\text{Conv}3\times3,\ 128\), then pool.

Output: \(56\times56\times128\)

Block 3

Input \(56\times56\times128\). Three convolutions \(\text{Conv}3\times3,\ 256\), then pool.

Output: \(28\times28\times256\)

Block 4

Input \(28\times28\times256\). Three convolutions \(\text{Conv}3\times3,\ 512\), then pool.

Output: \(14\times14\times512\)

Block 5

Input \(14\times14\times512\). Three convolutions \(\text{Conv}3\times3,\ 512\), then pool.

Output: \(7\times7\times512\)

6. Why Spatial Size Stays Constant Inside a Block

Every convolution uses \(f=3,\ s=1,\ p=1\). The output-size formula is:

\[n_{\text{out}}=\left\lfloor\frac{n+2p-f}{s}\right\rfloor+1\]

Substituting:

\[n_{\text{out}}=\frac{n+2(1)-3}{1}+1=n\]

Therefore a \(3\times3\) convolution with stride \(1\) and padding \(1\) preserves height and width. This is called same padding.

7. Why Pooling Halves the Spatial Dimensions

VGG uses \(2\times2\) max pooling, \(s=2\). For an input size \(n\):

\[n_{\text{out}}=\frac{n-2}{2}+1\]

For even \(n\), this becomes \(n_{\text{out}}=\dfrac{n}{2}\). Therefore:

\[224\rightarrow112\rightarrow56\rightarrow28\rightarrow14\rightarrow7\]

After each pooling stage: height is halved, width is halved, and channel depth usually increases.

8. Parameter-Count Formula

For a convolution layer:

\[P=(f_H f_W C_{\text{in}}+1)\,C_{\text{out}}\]

The \(+1\) is one bias for each filter. For VGG:

\[P=(3\times3\times C_{\text{in}}+1)\,C_{\text{out}}\]

A convolution layer's parameters depend on filter dimensions and number of filters — not on the spatial output size.

14. Important Design Pattern

\[\text{Spatial dimensions decrease while channel depth increases}\]

Specifically:

\[224\rightarrow112\rightarrow56\rightarrow28\rightarrow14\rightarrow7\]

while channels change as:

\[3\rightarrow64\rightarrow128\rightarrow256\rightarrow512\rightarrow512\]

As spatial resolution decreases, the network learns more abstract and numerous feature maps:

  • Early layers detect edges, color transitions, simple textures.
  • Middle layers detect corners, patterns, object parts.
  • Deep layers detect complex shapes, semantic object structures.

15. Receptive Field in VGG

The receptive field is the region of the original image that influences one activation. Stacking \(3\times3\) convolutions gradually increases it. With stride \(1\):

  • one \(3\times3\) convolution → \(3\times3\) receptive field,
  • two stacked → \(5\times5\),
  • three stacked → \(7\times7\).

The general relation for \(L\) stacked \(3\times3\), stride-1 convolutions is:

\[R=1+2L\]

So \(L=1\Rightarrow R=3\), \(L=2\Rightarrow R=5\), \(L=3\Rightarrow R=7\). Pooling increases the receptive field even more because it introduces stride.

16. Main Technical Concepts of VGG

  1. Uniform architecture — nearly all conv layers use \(3\times3,\ s=1,\ p=1\).
  2. Increased depth — depth substantially improves image representation.
  3. Small convolution filters — large filters replaced by stacks of small ones.
  4. Progressive channel expansion — \(64\rightarrow128\rightarrow256\rightarrow512\).
  5. Periodic spatial downsampling — max pooling progressively reduces image size.
  6. ReLU activation — \(\text{ReLU}(z)=\max(0,z)\) after each conv and hidden FC.
  7. Large FC classifier — \(4096\rightarrow4096\rightarrow1000\), most of the parameters.
  8. Softmax output — probabilities over 1000 ImageNet classes.

17. Advantages of VGG

  • Simple and regular design — same small conv repeated throughout.
  • Strong feature extractor — pretrained VGG features useful for classification, detection, segmentation, transfer learning, perceptual loss.
  • Greater nonlinearity — more ReLU stages than one large conv.
  • Effective hierarchical feature learning — low-level to complex semantic features.
  • Easy to analyze — simpler to draw/compute than Inception or ResNet.

18. Limitations of VGG

  • Very high parameter count — approximately \(138.4\) million.
  • Large model size — with 32-bit floats: \(138.4\text{M}\times4\text{ bytes}\approx553.4\) MB (parameters only).
  • High computational cost — many convolutions at large spatial resolutions.
  • Large FC layers — parameter-inefficient classifier.
  • No skip connections — unlike ResNet, no shortcut path for gradients.
  • Hard to train deeper — plain deep stacks suffer vanishing gradients, degradation, slow optimization.
  • Not for low-resource devices — MobileNet, ShuffleNet, EfficientNet are far more deployment-efficient.

20. Common Exam Questions

Q1. Why is VGG-16 called VGG-16?

VGG-16 contains 16 trainable weight layers: 13 convolutional and 3 fully connected. Pooling and activation layers are not counted because they contain no trainable weights.

Q2. What is the main idea of VGG?

Build a deep CNN using repeated small \(3\times3\) convolutions with stride 1 and same padding, combined with periodic \(2\times2\) max pooling. Stacking small filters produces large effective receptive fields with fewer parameters and more nonlinear activation stages than one large filter.

Q3. Why does VGG use two \(3\times3\) filters instead of one \(5\times5\)?

Two stacked \(3\times3\) filters give an effective \(5\times5\) receptive field. They require \(18C^2\) weights vs \(25C^2\) for one \(5\times5\), and introduce two nonlinear activation stages rather than one.

Q4. Why is VGG computationally expensive?

VGG has many convolution layers on large feature maps, and its classifier contains two 4096-unit FC layers accounting for most of its ~138 million parameters.

Q5. What are the output dimensions after the five pooling layers?

Starting from \(224\times224\times3\): \(112\times112\times64\), \(56\times56\times128\), \(28\times28\times256\), \(14\times14\times512\), \(7\times7\times512\).

Part IV — Inception Network

Parallel multi-scale convolution branches, 1×1 bottlenecks, and channel concatenation (GoogLeNet).

1. What Problem Does Inception Solve?

Different objects and features appear at different scales. A small pattern may need a \(1\times1\) or \(3\times3\) filter, while a larger pattern may need a \(5\times5\) filter. Instead of manually selecting one filter size, Inception performs several operations in parallel:

\[1\times1\text{ Conv},\quad 3\times3\text{ Conv},\quad 5\times5\text{ Conv},\quad \text{Pooling}\]

The network learns which features from each scale are useful.

2. Structure of an Inception Module

A standard Inception module has four parallel branches whose outputs are concatenated along the channel dimension.

\[\boxed{\text{Output}=\operatorname{Concat}(B_1,B_2,B_3,B_4)}\]

Inception uses concatenation, not addition.

3. Why 1×1 Convolutions Before 3×3 and 5×5?

The \(1\times1\) convolution reduces the number of channels before an expensive convolution. For example \(28\times28\times192\) can first be converted to \(28\times28\times16\); the subsequent \(5\times5\) convolution then processes only 16 channels instead of 192.

Therefore, \(1\times1\) convolution provides:

  • channel reduction,
  • lower parameter count,
  • lower computational cost,
  • channel mixing,
  • additional nonlinearity when followed by an activation.

It is called a bottleneck layer or dimension-reduction layer.

4. Output Shape of an Inception Module

Suppose the input is \(28\times28\times192\) and the branches produce 64, 128, 32, and 32 channels. All branches use stride 1 and same padding, so spatial dimensions remain \(28\times28\). The outputs are concatenated:

\[64+128+32+32=256\]
\[\boxed{\text{Output shape}=28\times28\times256}\]

The channel counts are added because concatenation occurs along the depth dimension.

5. The Key Inception Cost Problem

Consider \(28\times28\times192\) followed directly by a \(5\times5\) convolution with 32 filters. Ignore biases and BN.

Without a bottleneck

\[P_{\text{direct}}=5\times5\times192\times32=\boxed{153{,}600}\]
\[28\times28\times5\times5\times192\times32=\boxed{120{,}422{,}400\text{ MACs}}\]

With a 1×1 bottleneck

Reduce channels \(192\rightarrow16\) with \(1\times1\), then apply \(5\times5,\ 32\) filters.

\[1\times1\times192\times16=3{,}072,\qquad 5\times5\times16\times32=12{,}800\]
\[\boxed{P_{\text{bottleneck}}=3{,}072+12{,}800=15{,}872}\]
\[28\times28\times15{,}872=\boxed{12{,}443{,}648\text{ MACs}}\]

Saving

\[\frac{120{,}422{,}400}{12{,}443{,}648}\approx\boxed{9.68\times\text{ less computation}}\]

This is the key numerical idea behind Inception.

6. Overall GoogLeNet / Inception Architecture

Initial convs & pooling → repeated Inception modules → spatial downsampling → Global Avg Pool → Classifier → Softmax

The original GoogLeNet also used auxiliary classifiers connected to intermediate layers during training. Their purposes: improve gradient flow, provide additional supervision, and reduce overfitting through a regularizing effect. They are normally removed or ignored during final inference.

7. Advantages & Limitations of Inception

Advantages

  • extracts features at multiple scales,
  • uses computation-efficient bottlenecks,
  • fewer parameters than large plain CNNs,
  • replaces large FC layers with global average pooling,
  • flexible parallel architecture.

Limitations

  • complicated to design and implement,
  • many parallel branches,
  • channel dimensions must be carefully managed,
  • less regular than VGG or ResNet,
  • concatenation can increase memory usage.
Inception processes multiple receptive-field sizes in parallel and concatenates their outputs.

Part V — ResNet Architecture

Residual Network — the skip connection, and how it enables very deep CNNs to train.

Overview: Residual Learning

ResNet stands for Residual Network. Its key innovation is the skip connection (shortcut / identity connection). The main idea:

\[\text{Instead of learning }H(x),\text{ learn the residual }F(x)=H(x)-x\]

so that:

\[H(x)=F(x)+x\]

This simple addition allows very deep CNNs to train effectively. The lecture shows the shortcut carrying the input directly to a later layer, where it is added to the transformed output.

1. Why Was ResNet Needed?

Before ResNet, adding more layers did not always improve a CNN. Compare a 20-layer plain network to a 56-layer plain network. The deeper network should theoretically represent everything the shallower one can (extra layers could learn identity mappings). Yet in practice the deeper plain network could have higher training error, harder optimization, and degraded accuracy. This is the degradation problem.

Overfitting

Training error is low, but validation error is high.

Degradation problem

Even the training error becomes worse when more layers are added. ResNet was designed to make deep networks easier to optimize.

2. Main Idea of Residual Learning

Consider a normal block that should learn \(H(x)\). In a residual block, the stacked layers learn \(F(x)=H(x)-x\). Then the output becomes \(y=F(x)+x\), where \(x\) is the shortcut input, \(F(x)\) the residual transformation, and \(F(x)+x\) the combined output. Usually an activation follows the addition:

\[y=\operatorname{ReLU}(F(x)+x)\]

The input bypasses two transformations and is added before the final activation.

3. Why Is Learning a Residual Easier?

Suppose the optimal mapping is close to identity: \(H(x)\approx x\). A plain network must learn \(H(x)=x\). A residual network only needs \(F(x)=H(x)-x\approx0\). Learning a function close to zero is often easier than forcing several nonlinear layers to reproduce the identity exactly.

If the residual layers learn \(F(x)=0\), then \(y=F(x)+x=x\). Therefore extra residual blocks can behave like identity mappings instead of harming the network.

4. Basic Residual Block

A simple residual block contains two \(3\times3\) convolution layers.

Main branch: x → Conv → BN → ReLU → Conv → BN Shortcut: x → x Add: z = F(x) + x Output: y = ReLU(z)

A common mathematical representation:

\[z^{[l+1]}=W^{[l+1]}a^{[l]}+b^{[l+1]}\] \[a^{[l+1]}=g\!\left(z^{[l+1]}\right)\] \[z^{[l+2]}=W^{[l+2]}a^{[l+1]}+b^{[l+2]}\] \[a^{[l+2]}=g\!\left(z^{[l+2]}+a^{[l]}\right)\]

The shortcut skips from \(a^{[l]}\) directly to the addition at layer \(l+2\).

5. Identity Shortcut

The simplest shortcut is \(y=F(x)+x\). It is called an identity shortcut because it performs no transformation. It introduces:

\[0\text{ extra parameters}\]

and almost no extra computational cost. However, addition is only possible when the two tensors have the same dimensions. If \(F(x)\in\mathbb{R}^{H\times W\times C}\), then \(x\) must also have shape \(H\times W\times C\).

6. What Happens When Dimensions Differ?

Suppose the residual branch changes spatial dimensions, channel count, or both. Then \(F(x)+x\) cannot be computed directly. For example \(x:56\times56\times64\) but \(F(x):28\times28\times128\). A projection shortcut is used:

\[y=F(x)+W_s x\]

Here \(W_s\) is usually a \(1\times1\) convolution. It can change the channel count, reduce spatial dimensions via stride, and make the shortcut compatible with the residual output. For example \(1\times1\) Conv, stride \(2\), 128 filters converts \(56\times56\times64\) into \(28\times28\times128\). Then addition becomes valid.

7. Identity Block vs Convolutional Block

Identity block

Input and output dimensions identical: \(y=F(x)+x\). Shortcut unchanged, no extra shortcut parameters, usually stride \(1\), same number of input and output channels.

Convolutional / projection block

Input and output dimensions differ: \(y=F(x)+W_s x\). Shortcut uses a \(1\times1\) convolution, may use stride \(2\), changes spatial resolution or channel count, and contains trainable parameters.

8. Basic Block

The basic block is mainly used in ResNet-18 and ResNet-34. Its structure is \(3\times3,\ C\rightarrow3\times3,\ C\). The residual mapping is \(F(x)=W_2\,g(W_1 x)\), then \(y=g(F(x)+x)\).

x → [3×3 Conv] → ReLU → [3×3 Conv] → + → ReLU └──────────── shortcut ──────────┘

9. Bottleneck Block

The bottleneck block is used in deeper networks: ResNet-50, ResNet-101, ResNet-152. Its structure is \(1\times1\rightarrow3\times3\rightarrow1\times1\):

  1. \(1\times1\) convolution reduces channels.
  2. \(3\times3\) convolution processes spatial information.
  3. \(1\times1\) convolution restores or expands channels.

For example \(256\rightarrow64\rightarrow64\rightarrow256\). The block can be written:

\[F(x)=W_3\,g\!\left(W_2\,g(W_1 x)\right),\qquad y=g(F(x)+x)\]

10. Why Is It Called a Bottleneck?

The central representation is narrower than the block input and output: \(256\rightarrow64\rightarrow64\rightarrow256\). The \(1\times1\) convolution first reduces the number of channels, so the expensive \(3\times3\) convolution operates on only 64 channels instead of 256. This reduces computational cost substantially.

11. Bottleneck Parameter Comparison

Suppose input and output both have 256 channels.

Without bottleneck

Two \(3\times3\) convolutions, \(3\times3\times256\times256\) per convolution:

\[2(9\times256^2)=1{,}179{,}648\]

With bottleneck

Assume \(256\rightarrow64\rightarrow64\rightarrow256\):

  • First \(1\times1\): \(1\times1\times256\times64=16{,}384\)
  • Middle \(3\times3\): \(3\times3\times64\times64=36{,}864\)
  • Final \(1\times1\): \(1\times1\times64\times256=16{,}384\)
\[16{,}384+36{,}864+16{,}384=\boxed{69{,}632}\]

This is dramatically smaller than \(1{,}179{,}648\). Bottleneck blocks make very deep ResNets computationally feasible.

19. Why Skip Connections Improve Backpropagation

Consider \(y=F(x)+x\). During backpropagation:

\[\frac{\partial L}{\partial x}=\frac{\partial L}{\partial y}\frac{\partial y}{\partial x}\]

Since:

\[\frac{\partial y}{\partial x}=\frac{\partial F(x)}{\partial x}+1\]

we obtain:

\[\frac{\partial L}{\partial x}=\frac{\partial L}{\partial y}\left(\frac{\partial F(x)}{\partial x}+1\right)\]

The \(+1\) term creates a direct gradient path. Even if \(\dfrac{\partial F(x)}{\partial x}\) becomes very small, the gradient can still pass through the identity shortcut. This helps reduce the vanishing-gradient problem.

20. Important Clarification

ResNet does not completely eliminate vanishing gradients under all conditions. Instead, it provides shorter gradient routes, improves information flow, makes optimization of deep networks easier, and reduces degradation.

Best exam wording: Residual connections alleviate the vanishing-gradient and degradation problems by providing direct identity paths for activations and gradients.

21. Addition vs Concatenation

ResNet uses element-wise addition \(y=F(x)+x\). If both tensors have shape \(H\times W\times C\), the output also has shape \(H\times W\times C\) — channel count does not increase.

This differs from DenseNet, which uses concatenation \(y=[x,F(x)]\), increasing the channel dimension. Example: \(x:H\times W\times64\), \(F(x):H\times W\times32\) gives DenseNet output \(H\times W\times96\). ResNet addition would require equal channels and keep the output channel count the same.

22. Shape Rules for Residual Addition

To add two tensors, they must have the same height, width, and channel count. If \(x\in\mathbb{R}^{H\times W\times C}\), then \(F(x)\in\mathbb{R}^{H\times W\times C}\). If not, use \(W_s x\). This is one of the most important technical rules in ResNet.

25. Example: Downsampling Residual Block

Input \(56\times56\times64\). Main branch: (1) \(3\times3\), 128 filters, stride 2, padding 1; (2) \(3\times3\), 128 filters, stride 1, padding 1. Shortcut: \(1\times1\), 128 filters, stride 2.

Main-path first output

\[H_{\text{out}}=\left\lfloor\frac{56+2(1)-3}{2}\right\rfloor+1=\left\lfloor\frac{55}{2}\right\rfloor+1=27+1=28\]

Therefore \(28\times28\times128\). The second convolution preserves this shape, and the shortcut also produces \(28\times28\times128\). Therefore addition is valid.

26. Batch Normalization in ResNet

A typical ResNet convolution is followed by batch normalization, which helps stabilize activations, permit larger learning rates, improve convergence, and reduce sensitivity to initialization. Conv bias is often disabled because BN already includes a learnable shift.

When counting parameters, questions may use either \(f^2 C_{\text{in}} C_{\text{out}}\) or \((f^2 C_{\text{in}}+1)C_{\text{out}}\). Use the convention stated; if none is stated, mention the assumption clearly.

27. Original vs Pre-activation ResNet

Original post-activation block

Conv → BN → ReLU → Conv → BN → Add → ReLU

The activation occurs after shortcut addition.

Pre-activation block

BN → ReLU → Conv → BN → ReLU → Conv → Add

Normalization and activation occur before convolutions. Advantages: cleaner identity path, improved gradient flow, easier training of extremely deep networks.

For your midterm, the original block is more likely unless pre-activation is specifically mentioned.

28. Global Average Pooling

Modern ResNet normally uses global average pooling instead of the large FC head used by VGG. If the final feature map is \(7\times7\times2048\), GAP computes one average per channel:

\[7\times7\times2048\rightarrow1\times1\times2048\]

This produces a vector of length 2048. Advantages: no trainable pooling parameters, fewer classifier parameters, less overfitting, compact spatial handling. This is one reason ResNet is much more parameter-efficient than VGG.

31. ResNet vs Highway Network

Highway networks use learned gates:

\[y=H(x)\,T(x)+x\,C(x)\]

ResNet uses ungated addition \(y=F(x)+x\). Thus ResNet shortcuts are simpler and usually parameter-free when dimensions match. This distinction is less likely in your exam but useful conceptually.

32. Advantages of ResNet

  • Enables very deep networks — 50, 101, 152 layers become practical.
  • Better gradient flow — identity shortcuts provide direct gradient paths.
  • Reduces degradation — adding layers is less likely to increase training error.
  • Efficient feature learning — residual blocks learn corrections to existing features.
  • Flexible design — combines with bottleneck blocks, grouped convolutions, attention, depthwise convolutions.
  • Strong transfer-learning backbone — classification, detection, segmentation, medical imaging, scene understanding.

33. Limitations of ResNet

  • Addition requires matched dimensions — projection shortcuts may be necessary.
  • Deep variants remain expensive — ResNet-101/152 still require substantial computation.
  • Feature reuse less explicit than DenseNet — addition merges rather than preserves maps.
  • Information can be compressed during addition — two signals combined into one tensor.
  • Still relies heavily on convolution — newer attention/hybrid models may do better on some tasks.
  • Skip connections do not guarantee perfect optimization — initialization, normalization, learning rate, and data still matter.

\[\text{Basic block:}\quad 3\times3\rightarrow3\times3\]
\[\text{Bottleneck block:}\quad 1\times1\rightarrow3\times3\rightarrow1\times1\]
  • ResNet-18 & ResNet-34 use basic blocks.
  • ResNet-50, 101, 152 use bottleneck blocks.
  • Connection: element-wise addition, not concatenation.
  • Main benefits: better gradient flow, easier optimization, reduced degradation, very deep networks.

35. Common Exam Traps

  1. Saying ResNet completely eliminates vanishing gradients.
  2. Confusing degradation with overfitting.
  3. Saying the shortcut concatenates features.
  4. Adding tensors with different dimensions.
  5. Forgetting the projection shortcut.
  6. Counting ReLU and pooling layers in the ResNet number.
  7. Saying ResNet-50 has 50 residual blocks.
  8. Forgetting that ResNet-50 uses bottleneck blocks.
  9. Assuming an identity shortcut has parameters.
  10. Forgetting stride 2 during stage transitions.
  11. Calling every shortcut a \(1\times1\) convolution.
  12. Confusing the bottleneck block with MobileNetV2's inverted residual.

36. Exam-Style Questions and Answers

Q1. What is residual learning?

Residual learning trains a block to learn \(F(x)=H(x)-x\) instead of directly learning \(H(x)\). The desired mapping is reconstructed as \(H(x)=F(x)+x\). This makes identity-like mappings easier to learn and improves optimization in deep networks.

Q2. Why do ResNets work better when made deeper?

ResNets use identity shortcuts that allow activations and gradients to bypass intermediate layers. These paths improve gradient flow, make identity mappings easy to represent, and reduce the degradation problem in very deep plain networks.

Q3. Difference between identity and projection shortcuts?

An identity shortcut passes \(x\) unchanged: \(y=F(x)+x\); used when dimensions match, no trainable parameters. A projection shortcut applies a transformation: \(y=F(x)+W_s x\); used when spatial size or channel count changes, commonly via a \(1\times1\) convolution.

Q4. Why does ResNet-50 use bottleneck blocks?

The bottleneck reduces channel dimensionality before the expensive \(3\times3\) convolution and restores it afterward, greatly reducing parameter and computational cost and making deeper networks practical.

Q5. How does a skip connection help gradients?

For \(y=F(x)+x\), the derivative includes \(\dfrac{\partial y}{\partial x}=\dfrac{\partial F}{\partial x}+1\). The identity term provides a direct gradient path, helping gradients propagate through many layers.

Part VI — Wide ResNet · ResNeXt · ConvNeXt

Three ways to move past plain ResNet: widen it, add cardinality, or modernize it.

Quick Distinction

\[\boxed{\text{Wide ResNet: increase width}}\] \[\boxed{\text{ResNeXt: increase cardinality}}\] \[\boxed{\text{ConvNeXt: modernize a ResNet-style CNN}}\]

WRN · 1. What Is Wide ResNet?

Wide Residual Network (WRN) modifies ResNet by using fewer layers but more channels per layer. Instead of very deep + thin, WRN uses:

\[\boxed{\text{shallower}+\text{wider}}\]

The original WRN work showed that increasing width could improve accuracy and training efficiency compared with extremely deep, thin residual networks.

WRN · 2. What Does WRN-\(d\)-\(k\) Mean?

\[\boxed{\text{WRN-}d\text{-}k}\]

where \(d\) = total network depth and \(k\) = widening factor. For example \(\boxed{\text{WRN-28-10}}\) means 28 layers with channel widths ≈ 10× the thin baseline. A stage with 64 channels becomes ≈ \(64\times10=640\) channels.

WRN · 3. Wide ResNet Block

A typical WRN block still uses the ResNet equation \(\boxed{y=F(x)+x}\). The residual branch commonly contains:

BN → ReLU → 3×3 Conv → BN → ReLU → 3×3 Conv

A dropout layer may be placed between the two convolutions. The main difference from ordinary ResNet is not the shortcut — it is the much larger number of channels inside the residual block.

WRN · 4. How Widening Affects Parameters

Two \(3\times3\) convolutions each with \(C\) input/output channels (ignoring biases):

\[P_{\text{thin}}=2(3\times3\times C\times C)=\boxed{18C^2}\]

Multiplying channels by widening factor \(k\) (\(C\rightarrow kC\)):

\[P_{\text{wide}}=18(kC)^2=\boxed{18k^2C^2}\]

Parameters grow approximately with \(\boxed{k^2}\).

Example

\(C=64,\ k=4\):

\[P_{\text{thin}}=18(64)^2=\boxed{73{,}728},\qquad P_{\text{wide}}=18(256)^2=\boxed{1{,}179{,}648}\]

Four times wider → \(\boxed{4^2=16\times}\) more convolution parameters.

ResNeXt · 6. The Main Idea

ResNeXt introduces a new scaling dimension called cardinality — the number of parallel transformations (groups) inside a residual block. Its structure is:

\[\boxed{\text{Split}\rightarrow\text{Transform}\rightarrow\text{Aggregate}}\]

Several transformations process the input in parallel, and their outputs are aggregated before the shortcut is added:

\[\boxed{y=x+\sum_{i=1}^{C}T_i(x)}\]

where \(C\) is the cardinality.

ResNeXt · 7. How the Block Is Implemented

Conceptually there are several parallel branches. In practice they are efficiently implemented with a grouped \(3\times3\) convolution:

1×1 reduce → 3×3 grouped conv → 1×1 expand (then y = F(x) + x)

The grouped convolution divides channels into separate groups, transforms within each group, and combines all group outputs.

ResNeXt · 8. What Does ResNeXt-50 (32×4d) Mean?

In \(\boxed{\text{ResNeXt-50 }32\times4d}\): 50 = depth, 32 = cardinality (number of groups), \(4d\) = each group has width 4. Total width entering the grouped convolution:

\[32\times4=128\text{ channels}\]

Don't confuse: cardinality 32 (number of groups), group width 4 (channels per group), total grouped width 128.

ResNeXt · 9. Grouped-Convolution Parameter Formula

\[P_{\text{normal}}=K^2C_{\text{in}}C_{\text{out}}\]

For grouped convolution with \(g\) groups:

\[\boxed{P_{\text{group}}=\frac{K^2C_{\text{in}}C_{\text{out}}}{g}}\]

Grouped convolution reduces the parameters and MACs of that operation approximately by a factor of \(g\).

ResNeXt · 10. Worked Bottleneck Calculation

Block \(256\rightarrow128\rightarrow128\rightarrow256\): first \(1\times1\), then \(3\times3\) grouped (\(g=32\)), then final \(1\times1\). Ignore biases/BN.

\[\text{First }1\times1:\ 256\times128=32{,}768\] \[\text{Grouped }3\times3:\ \frac{3\times3\times128\times128}{32}=\boxed{4{,}608}\] \[\text{Final }1\times1:\ 128\times256=32{,}768\]
\[P=32{,}768+4{,}608+32{,}768=\boxed{70{,}144}\]

Without groups, the middle \(3\times3\) alone would need \(3\times3\times128\times128=147{,}456\) parameters.

Under comparable complexity, increasing cardinality can be more effective than simply increasing depth or width.

ConvNeXt · 12. What Is ConvNeXt?

ConvNeXt is a pure convolutional network created by progressively modernizing a ResNet using design choices from successful hierarchical vision models. It does not replace convolution with self-attention — it shows a carefully redesigned CNN can remain a competitive general-purpose vision backbone.

\[\boxed{\text{Modernize ResNet while remaining entirely convolutional}}\]

ConvNeXt · 13. The ConvNeXt Block

\[\boxed{7\times7\text{ DW conv}\rightarrow\text{LayerNorm}\rightarrow1\times1\text{ expand}\rightarrow\text{GELU}\rightarrow1\times1\text{ project}}\]

If the block input has \(C\) channels: the \(7\times7\) depthwise keeps \(C\); the first pointwise expands \(C\rightarrow4C\); the second projects \(4C\rightarrow C\). The arrangement resembles an inverted bottleneck.

ConvNeXt · 14. Key Changes From ResNet

  • Patch-style stem: \(\boxed{4\times4\text{ conv, stride }4}\) instead of \(7\times7\) conv + max pool.
  • Larger depthwise kernel: \(\boxed{7\times7\text{ depthwise}}\) instead of repeated \(3\times3\).
  • Inverted bottleneck: \(C\rightarrow4C\rightarrow C\).
  • LayerNorm rather than heavy BatchNorm use.
  • GELU replaces most ReLU activations.
  • Fewer activations & norms — only strategically placed ones retained.
  • Separate downsampling layers — norm + stride-2 conv between stages.

Part VII — MobileNet V1 & V2

Depthwise-separable convolution, the V1 block, and V2's expansion–depthwise–projection inverted residual.

1. Why Was MobileNet Introduced?

MobileNet was designed for resource-limited devices: mobile phones, embedded systems, robots, edge devices. A normal CNN uses expensive standard convolutions; MobileNet reduces computation and parameters mainly through depthwise-separable convolution.

\[\text{Main goal: good accuracy with low computation and a small model}\]

2. Main Building Block of MobileNetV1

MobileNetV1 replaces one standard convolution with two operations:

\[\text{Depthwise convolution}\rightarrow\text{Pointwise convolution}\]

Depthwise convolution

A separate spatial filter is applied to each input channel. For an input with \(M\) channels: number of \(3\times3\) filters \(=M\), each filter of size \(3\times3\times1\), channels processed independently. It detects spatial patterns but does not combine channels.

Pointwise convolution

A \(1\times1\) convolution combines information across channels (\(1\times1\times M\)). Each pointwise filter sees all \(M\) input channels.

3. Depthwise vs Standard Convolution

Suppose the input has \(M\) channels and we want \(N\) output channels.

Standard convolution

Each of the \(N\) filters has size \(K\times K\times M\), so every filter simultaneously extracts spatial features and combines channels.

Depthwise-separable convolution

  1. Depthwise \(K\times K\): spatial filtering, one filter per channel.
  2. Pointwise \(1\times1\): channel mixing and creation of \(N\) output channels.

This factorization is the main source of MobileNetV1's efficiency.

4. The Key MobileNetV1 Calculation

Assume output map \(H\times W\), kernel \(K\times K\), input channels \(M\), output channels \(N\). Biases ignored (BN follows).

Standard convolution

\[\boxed{P_{\text{standard}}=K^2MN}\qquad \boxed{C_{\text{standard}}=HWK^2MN}\]

Depthwise-separable

\[P_{\text{depthwise}}=K^2M,\qquad P_{\text{pointwise}}=MN\]
\[\boxed{P_{\text{separable}}=K^2M+MN}\qquad \boxed{C_{\text{separable}}=HW(K^2M+MN)}\]

Relative cost

\[\frac{C_{\text{separable}}}{C_{\text{standard}}}=\frac{K^2M+MN}{K^2MN}=\boxed{\frac1N+\frac1{K^2}}\]

5. Worked MobileNetV1 Calculation

Suppose \(H=W=112,\ K=3,\ M=32,\ N=64\).

Standard parameters

\[P_{\text{standard}}=3^2(32)(64)=9(2048)=\boxed{18{,}432}\]

Depthwise + pointwise

\[P_{\text{depthwise}}=3^2(32)=288,\qquad P_{\text{pointwise}}=32(64)=2{,}048\]
\[P_{\text{separable}}=288+2{,}048=\boxed{2{,}336}\]

Efficiency

\[\frac{18{,}432}{2{,}336}\approx7.89\]

Depthwise-separable convolution uses about \(\boxed{7.9\times}\) fewer parameters and MACs — roughly \(\boxed{87.3\%}\) less computation for this layer.

6. Overall MobileNetV1 Architecture

The general structure is a standard \(3\times3\) convolution, then repeated blocks:

\[\boxed{3\times3\text{ depthwise}\rightarrow1\times1\text{ pointwise}}\]
Input → 3×3 Conv → [3×3 DW → 1×1 PW]×… → Global Avg Pool → Classifier → Softmax

BN and activation normally follow the depthwise and pointwise convolutions. Spatial resolution is reduced using stride-2 depthwise convolutions, while the number of channels generally increases.

7. Width and Resolution Multipliers

Width multiplier \(\alpha\)

Reduces the number of channels: \(M\rightarrow\alpha M,\ N\rightarrow\alpha N\), with \(0<\alpha\le1\). For example \(\alpha=0.5\) uses roughly half as many channels. Pointwise-convolution cost decreases approximately with \(\alpha^2\).

Resolution multiplier \(\rho\)

Reduces resolution: \(H\rightarrow\rho H,\ W\rightarrow\rho W\). Spatial computation decreases approximately with \(\rho^2\).

  • smaller \(\alpha\): fewer channels,
  • smaller \(\rho\): smaller feature maps,
  • both improve speed but may reduce accuracy.

8. What Motivated MobileNetV2?

MobileNetV1 is efficient, but its block has limitations:

  • it processes features directly in relatively narrow channel spaces,
  • repeated nonlinear activations may destroy useful information,
  • it has no strong residual structure between most blocks,
  • its representational capacity is limited compared with a block that temporarily expands its features.

MobileNetV2 introduces:

\[\text{Inverted residuals and linear bottlenecks}\]

9. The MobileNetV2 Inverted Residual Block

\[\boxed{\text{Expansion}\rightarrow\text{Depthwise}\rightarrow\text{Linear projection}}\]

Stage 1 — Expansion

A \(1\times1\) convolution increases channels \(C\rightarrow tC\), where \(t\) is the expansion factor (commonly \(t=6\)). Activation (ReLU6) follows.

Stage 2 — Depthwise convolution

A \(3\times3\) depthwise convolution processes each expanded channel spatially. Activation follows again.

Stage 3 — Linear projection

A \(1\times1\) convolution reduces channels \(tC\rightarrow C_{\text{out}}\). No ReLU is applied after this projection.

10. Why “Inverted Residual”?

A traditional ResNet bottleneck follows wide → narrow → wide. MobileNetV2 does the opposite:

\[\boxed{\text{narrow}\rightarrow\text{wide}\rightarrow\text{narrow}}\]

The input and output are low-dimensional bottlenecks, while the middle representation is expanded. The residual connection joins the narrow input and narrow output:

\[\boxed{y=x+F(x)}\]

That is why the block is called an inverted residual.

11. Why Is the Final Projection Linear?

The final low-dimensional feature space contains compressed information. Applying ReLU there could remove all negative values (\(\operatorname{ReLU}(z)=0\) for \(z<0\)). In a narrow space, this may permanently destroy important information. Therefore:

\[\text{No activation after the final }1\times1\text{ projection}\]

This is the linear bottleneck. ReLU6 is used in the expanded space, where there are more channels and therefore less risk of severe information loss.

12. When Is the Residual Connection Used?

The identity shortcut is used only when:

  1. stride \(=1\), and
  2. input channels \(=\) output channels.

Then \(y=x+F(x)\). If stride is \(2\), the spatial dimensions change, so addition is impossible. If the output channel count differs, the shortcut is also omitted. Unlike many ResNet blocks, MobileNetV2 normally does not add a projection shortcut merely to force shapes to match.

13. Parameters in a MobileNetV2 Block

Given input channels \(C_{\text{in}}\), expansion factor \(t\), expanded channels \(tC_{\text{in}}\), output channels \(C_{\text{out}}\), \(3\times3\) depthwise:

\[P_{\text{expand}}=C_{\text{in}}(tC_{\text{in}}),\quad P_{\text{depthwise}}=3^2(tC_{\text{in}}),\quad P_{\text{project}}=(tC_{\text{in}})C_{\text{out}}\]
\[\boxed{P=tC_{\text{in}}^2+9tC_{\text{in}}+tC_{\text{in}}C_{\text{out}}}\]

Biases and batch-normalization parameters ignored.

Numerical example

Input \(56\times56\times24\), \(t=6\), \(C_{\text{out}}=24\). Expanded channels \(6(24)=144\).

\[\text{Expansion: }24(144)=3{,}456\] \[\text{Depthwise: }3^2(144)=1{,}296\] \[\text{Projection: }144(24)=3{,}456\]
\[P=3{,}456+1{,}296+3{,}456=\boxed{8{,}208}\]

Because stride is \(1\) and both input and output have 24 channels, a residual connection can be used.

Part VIII — SqueezeNet · ShuffleNet · SENet

Three easily-confused efficiency ideas: fewer parameters, cheaper computation, and channel attention.

Quick Distinction

\[\boxed{\text{SqueezeNet = fewer parameters}}\] \[\boxed{\text{ShuffleNet = efficient grouped convolution}}\] \[\boxed{\text{SENet = channel attention}}\]

SqueezeNet · 1. Why Introduced?

SqueezeNet aims for competitive accuracy with a very small number of parameters:

\[\boxed{\text{Reduce model size without severely reducing accuracy}}\]

A smaller network gives less storage, faster model transfer, easier embedded deployment, and lower memory usage. SqueezeNet reduces parameters mainly using the Fire module.

SqueezeNet · 2. The Fire Module

A Fire module has two stages: \(\boxed{\text{Squeeze layer}\rightarrow\text{Expand layer}}\).

Squeeze layer: only \(1\times1\) convolutions, \(C_{\text{in}}\rightarrow S\) (small), reducing channels entering the \(3\times3\) filters.

Expand layer: two parallel branches (\(1\times1\) and \(3\times3\)) whose outputs are concatenated:

\[\boxed{\text{Fire output}=\operatorname{Concat}(\text{Expand }1\times1,\text{ Expand }3\times3)},\qquad C_{\text{out}}=E_1+E_3\]

SqueezeNet · 3. Three Parameter-Reduction Strategies

Strategy 1 — Replace 3×3 with 1×1 filters

A \(1\times1\) conv needs \(C_{\text{in}}C_{\text{out}}\) weights; a \(3\times3\) needs \(9C_{\text{in}}C_{\text{out}}\). So \(1\times1\) uses nine times fewer weights for the same channels.

Strategy 2 — Reduce input channels of 3×3 filters

The squeeze layer reduces \(C_{\text{in}}\rightarrow S\), so the expand \(3\times3\) convolutions operate on only \(S\) channels.

Strategy 3 — Downsample late

SqueezeNet delays pooling so feature maps stay spatially large for longer, helping preserve accuracy because later layers still receive high-resolution features.

SqueezeNet · 4. Fire-Module Parameter Calculation

Input \(C_{\text{in}}=64\). Squeeze: 16 filters \(1\times1\); expand branch 1: 64 filters \(1\times1\); expand branch 2: 64 filters \(3\times3\). Ignore biases.

\[P_s=1\times1\times64\times16=1{,}024\] \[P_{e1}=1\times1\times16\times64=1{,}024\qquad(\text{expand input has 16 channels})\] \[P_{e3}=3\times3\times16\times64=9{,}216\]
\[P_{\text{Fire}}=1{,}024+1{,}024+9{,}216=\boxed{11{,}264}\]
\[C_{\text{out}}=64+64=\boxed{128}\]

The squeeze output is not concatenated with the final output — only the two expand branches are.

SqueezeNet · 5. Overall Architecture

Initial conv → repeated Fire modules → occasional max pool → final 1×1 conv → Global Avg Pool → Softmax
  • Fire modules are the main building blocks.
  • Large fully connected layers are avoided.
  • Global average pooling reduces classifier parameters.

ShuffleNet · 6. Why Introduced?

ShuffleNet targets devices with extremely limited computational budgets. Key operations:

\[\boxed{\text{Pointwise group convolution}+\text{Channel shuffle}+\text{Depthwise convolution}}\]

MobileNet reduces spatial-convolution cost via depthwise convolution, but \(1\times1\) pointwise convolutions can still be expensive. ShuffleNet reduces the cost of \(1\times1\) convolutions using grouped pointwise convolution.

ShuffleNet · 7. Grouped Convolution

In a normal convolution every output channel connects to every input channel. In grouped convolution, channels are divided into \(g\) independent groups; each group processes \(\dfrac{C_{\text{in}}}{g}\) input channels and produces \(\dfrac{C_{\text{out}}}{g}\) output channels.

\[P_{\text{standard}}=K^2C_{\text{in}}C_{\text{out}},\qquad \boxed{P_{\text{group}}=\frac{K^2C_{\text{in}}C_{\text{out}}}{g}}\]

Grouped convolution reduces parameters and computation by approximately a factor of \(g\).

ShuffleNet · 8. Grouped-Convolution Calculation

A \(1\times1\) convolution with \(C_{\text{in}}=64,\ C_{\text{out}}=128,\ g=4\):

\[P_{\text{normal}}=1\times1\times64\times128=\boxed{8{,}192}\] \[P_{\text{group}}=\frac{64\times128}{4}=\boxed{2{,}048}\]

Grouped convolution uses \(\boxed{4\times}\) fewer parameters and MACs for this operation.

ShuffleNet · 9. Why Channel Shuffle?

Grouped convolution creates a problem: channels in one group communicate only with channels in the same group. If grouped convolutions are stacked, information stays isolated inside separate groups. Channel shuffle rearranges channels so each group in the next layer receives channels from different previous groups.

The conceptual process: (1) divide channels into groups, (2) reshape into a 2-D group structure, (3) transpose group and channel-within-group dimensions, (4) flatten back.

\[\boxed{\text{Channel shuffle enables cross-group information exchange}}\]

Channel shuffle has no trainable parameters, adds very little cost, and prevents group isolation.

ShuffleNet · 10. The ShuffleNet Unit

\[\boxed{1\times1\text{ group conv}\rightarrow\text{channel shuffle}\rightarrow3\times3\text{ depthwise}\rightarrow1\times1\text{ group conv}}\]

Shortcut: if stride is 1 and dimensions match, \(\boxed{y=F(x)+x}\). If stride is 2, the main branch downsamples, the shortcut may use average pooling, and the branch outputs are commonly concatenated rather than added.

SENet · 11. The Main Idea

SENet = Squeeze-and-Excitation Network. Its key idea:

\[\boxed{\text{Learn how important each feature channel is}}\]

Not every channel is equally useful for every image. An SE block learns a separate importance weight per channel and rescales the feature maps — channel attention. SENet does not primarily reduce parameters like SqueezeNet.

SENet · 12. The Three Steps of an SE Block

Input tensor shape \(H\times W\times C\).

Step 1 — Squeeze

Global average pooling summarizes every channel \(H\times W\times C\rightarrow1\times1\times C\):

\[s_c=\frac{1}{HW}\sum_{i=1}^{H}\sum_{j=1}^{W}X_{i,j,c}\]

Step 2 — Excitation

The channel vector passes through two FC layers \(C\rightarrow\frac{C}{r}\rightarrow C\) (reduction ratio \(r\), commonly \(r=16\)), pattern \(FC\rightarrow ReLU\rightarrow FC\rightarrow Sigmoid\), producing weights \(\alpha_1,\ldots,\alpha_C\in(0,1)\).

Step 3 — Scale

\[\boxed{\tilde X_c=\alpha_c X_c}\]

Output shape remains \(\boxed{H\times W\times C}\) — only channel importance changes.

SENet · 13. SE-Block Parameter Calculation

\(C=256\), reduction \(r=16\), hidden dimension \(\frac{256}{16}=16\). Ignore biases.

\[\text{FC1: }256\rightarrow16:\ P_1=256\times16=4{,}096\] \[\text{FC2: }16\rightarrow256:\ P_2=16\times256=4{,}096\]
\[P_{\text{SE}}=4{,}096+4{,}096=\boxed{8{,}192}\]

General formula (ignoring biases):

\[\boxed{P_{\text{SE}}=\frac{2C^2}{r}}\]

Global average pooling has no trainable parameters.

SENet · 14. Where Is the SE Block Placed?

An SE block can be added to ResNet, Inception, MobileNet, EfficientNet. In an SE-ResNet block the flow is approximately:

x → convolutions → F(x) → SE recalibration → F̃(x)
\[\boxed{y=\tilde F(x)+x}\]

The SE block normally recalibrates the residual features before shortcut addition.

SqueezeNet: \(\boxed{\text{Small model using Fire modules}}\). SENet: \(\boxed{\text{Channel attention using squeeze and excitation}}\). The word "squeeze" appears in both, but their purposes are completely different.

Part IX — EfficientNet

Compound scaling of depth, width, and resolution; MBConv blocks with squeeze-and-excitation.

8. What Problem Does EfficientNet Solve?

CNN performance can be improved by scaling depth (more layers), width (more channels), or resolution (larger input images). Earlier architectures often scaled only one dimension. EfficientNet argues these should be scaled together in a balanced way:

\[\text{Compound scaling}\]

9. What Happens When Only One Dimension Is Scaled?

Increasing depth

Pros: learns more complex hierarchical features, increases the receptive field. Cons: harder optimization, diminishing accuracy improvement, greater latency.

Increasing width

Pros: captures more feature channels. Cons: shallow wide networks may fail to learn highly complex features; computation grows rapidly.

Increasing resolution

Pros: captures finer image details. Cons: spatial computation grows approximately with the square of resolution; deeper and wider networks may be required to process the extra information.

EfficientNet balances all three.

10. The Compound-Scaling Formula

EfficientNet uses a global scaling coefficient \(\phi\):

\[\boxed{d=\alpha^\phi},\qquad \boxed{w=\beta^\phi},\qquad \boxed{r=\gamma^\phi}\]

where \(d\) is the depth multiplier, \(w\) the width multiplier, \(r\) the resolution multiplier, and \(\alpha,\beta,\gamma\ge1\). CNN computation is approximately proportional to \(d\,w^2r^2\). The coefficients are chosen so that:

\[\boxed{\alpha\beta^2\gamma^2\approx2}\]

Therefore, increasing \(\phi\) by one approximately doubles the computational budget.

11. Worked Compound-Scaling Calculation

Suppose \(\alpha=1.2,\ \beta=1.1,\ \gamma=1.15\) and \(\phi=2\).

\[d=1.2^2=\boxed{1.44}\qquad(\text{≈1.44× deeper})\]
\[w=1.1^2=\boxed{1.21}\qquad(\text{≈1.21× wider})\]
\[r=1.15^2=\boxed{1.3225}\]

If the original resolution were 224: \(224(1.3225)\approx296\) (rounded to a hardware-compatible value).

Approximate computational increase

\[d\,w^2r^2=1.44(1.21)^2(1.3225)^2\approx\boxed{3.69\times}\]

So increasing \(\phi\) from 0 to 2 gives approximately four times the original computational budget.

12. The Main Building Block: MBConv

EfficientNet mainly uses the MBConv block, derived from MobileNetV2:

\[\boxed{1\times1\text{ expand}\rightarrow\text{depthwise conv}\rightarrow\text{Squeeze-and-Excitation}\rightarrow1\times1\text{ project}}\]

A residual connection is used when stride is 1 and input/output shapes match. The final projection is linear, like MobileNetV2. EfficientNet commonly uses MBConv1 and MBConv6 blocks with \(3\times3\) or \(5\times5\) depthwise kernels.

13. The Squeeze-and-Excitation Block

The SE block performs channel attention.

Step 1 — Squeeze

Global average pooling per channel: \(H\times W\times C\rightarrow1\times1\times C\). This summarizes each channel.

Step 2 — Excitation

A small neural network learns a weight for each channel: \(s_1,s_2,\ldots,s_C\).

Step 3 — Scale

\[X_c^{\text{new}}=s_c X_c\]

EfficientNet can thus emphasize informative channels and suppress less useful ones.

14. Activation & Regularization

The original EfficientNet uses the Swish activation (also called SiLU):

\[\boxed{\operatorname{Swish}(x)=x\,\sigma(x)}\]

Unlike ReLU, Swish is smooth and allows some negative values to pass. EfficientNet also uses batch normalization, dropout near the classifier, drop-connect / stochastic depth in residual blocks, and global average pooling instead of large FC layers.

15. EfficientNet-B0 to B7

EfficientNet first creates a baseline network \(\boxed{\text{EfficientNet-B0}}\), designed using neural architecture search. The same baseline is then scaled using compound scaling:

\[B0\rightarrow B1\rightarrow B2\rightarrow\cdots\rightarrow B7\]

As the model number increases: depth increases, channel width increases, input resolution increases, accuracy usually increases, and parameter count and computation also increase. The main difference between B0–B7 is therefore scale, not a completely different architectural principle.

16. EfficientNet vs MobileNet vs Inception

ArchitectureMain idea

EfficientNet inherits efficient ideas from MobileNetV2 but adds squeeze-and-excitation, Swish activation, and systematically balanced scaling of depth, width, and resolution. Unlike Inception, it does not depend primarily on several parallel kernel branches.

One-Minute Revision — Inception & EfficientNet

Inception

\[\boxed{1\times1,\;3\times3,\;5\times5,\;\text{pooling in parallel}}\] \[\boxed{\text{concatenated along channels}}\]

The \(1\times1\) convolution reduces channels, lowers \(3\times3\)/\(5\times5\) cost, and mixes channel information. Most important calculation:

\[\boxed{P_{\text{conv}}=K^2C_{\text{in}}C_{\text{out}}}\]

EfficientNet

\[\boxed{\text{Compound scaling of depth, width, and resolution}}\] \[d=\alpha^\phi,\qquad w=\beta^\phi,\qquad r=\gamma^\phi,\qquad \boxed{\alpha\beta^2\gamma^2\approx2}\]
\[\boxed{\text{expand}\rightarrow\text{depthwise}\rightarrow\text{SE}\rightarrow\text{linear project}}\]
Inception chooses several filter scales in parallel; EfficientNet scales the entire network's depth, width, and resolution in a balanced way.
