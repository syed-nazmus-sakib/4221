Q6(a) — DenseNet vs ResNet connectivity

How does DenseNet differ from ResNet in terms of connectivity pattern? Which architecture preserves features more effectively, and why?

The paper contains the question but no model solution; the following is the standard course-level answer.

ResNet

In a ResNet, a residual block learns \(F(x)\) and adds the original input through a shortcut:

\[ \boxed{y=F(x)+x} \]

So earlier information can bypass intermediate layers through an additive skip connection. Conceptually \(x \rightarrow F(x)\) while another path carries \(x\) directly, and the two are added: \(F(x)+x.\)

DenseNet

DenseNet uses concatenation rather than addition. Layer \(l\) receives the outputs of all preceding layers:

\[ \boxed{ x_l=H_l([x_0,x_1,\ldots,x_{l-1}]) } \]

where \([\cdots]\) means concatenation. So approximately \(x_0\rightarrow x_1\), \([x_0,x_1]\rightarrow x_2\), \([x_0,x_1,x_2]\rightarrow x_3\), and so on.

Which preserves features more explicitly?

\[ \boxed{\text{DenseNet}} \]

because it concatenates earlier feature maps instead of combining them through summation. In ResNet, \(F(x)+x\) mixes the two representations. In DenseNet, \([x_0,x_1,x_2,\ldots]\) keeps the earlier representations available as separate channels.

ResNet uses additive residual/skip connections, where a block output is \(F(x)+x\). DenseNet concatenates the feature maps from all previous layers and supplies them to each subsequent layer. DenseNet therefore preserves and reuses earlier features more explicitly because previous feature maps remain directly available rather than being merged through addition.

Q6(b) — Output size + computational cost

Input 64×64×128 · 64 filters · 5×5 · s=1 · valid

Given: \(\text{Input}=64\times64\times128\). Standard convolution: number of filters \(=64\), kernel \(=5\times5\), stride \(s=1\), padding = valid. Asks: (i) output size (ii) standard cost (iii) depthwise-separable cost (iv) compare.

(i) Output feature-map size

For valid convolution, \(p=0.\)

\[ n_{\text{out}} = \left\lfloor \frac{n+2p-k}{s} \right\rfloor+1. \quad n=64,\;p=0,\;k=5,\;s=1. \] \[ n_{\text{out}} = \frac{64-5}{1}+1 = 59+1 = 60. \]

There are 64 filters, therefore output depth is 64.

\[ \boxed{60\times60\times64} \]

(ii) Computational cost of standard convolution

One output value requires \(5\times5\times128 = 25\times128 = 3200\) multiplications/MACs. How many output values? \(60\times60\times64.\)

\[ MAC_{\text{std}} = 60\times60\times64\times5\times5\times128. \] \[ = 60\times60\times25\times128\times64. \]
\[ \boxed{ MAC_{\text{std}} = 737{,}280{,}000 } \qquad \boxed{737.28\text{ million MACs}} \]

Using the standard multiplication/MAC-count convention. If multiply and add are counted as two separate FLOPs, the FLOP figure is approximately twice this.

(iii) Depthwise-separable convolution cost

Two operations: \(\boxed{\text{Depthwise }5\times5}\) followed by \(\boxed{\text{Pointwise }1\times1}.\)

Depthwise: one \(5\times5\) filter for each of the 128 input channels.

\[ MAC_{DW} = 60\times60\times128\times5\times5 = 60\times60\times128\times25. \] \[ \boxed{ MAC_{DW}=11{,}520{,}000 } \]

Pointwise: \(64\) \(1\times1\) filters across 128 channels:

\[ MAC_{PW} = 60\times60\times128\times64. \quad \boxed{ MAC_{PW}=29{,}491{,}200 } \]
\[ MAC_{DS} = 11{,}520{,}000+29{,}491{,}200 \quad \boxed{ MAC_{DS}=41{,}011{,}200 } \quad \boxed{41.01\text{ million MACs}} \]

(iv) Comparison

Standard \(737.28M\) vs DS \(41.0112M.\)

\[ \frac{737.28}{41.0112} \approx 17.98. \]
\[ \boxed{\text{standard convolution costs about }18\times\text{ more}} \qquad \boxed{\text{DS convolution is about }18\times\text{ cheaper}} \]
\[ \frac{41.0112}{737.28} \approx 0.055625. \]
\[ \boxed{5.56\%} \quad \boxed{\text{computation reduced by approximately }94.44\%} \]

This is a very important calculation pattern.

Q6(c) — Complete CNN parameter count

224×224×3 → Conv1 20×5×5 same → Pool1 → Conv2 40×7×7 same → Pool2 → FC100 → FC5

First we need the dimensions.

\[ \text{Input } 224\times224\times3. \quad \text{Conv1 same: } 224\times224\times20. \quad \text{Pool1 2×2 s=2: } 112\times112\times20. \] \[ \text{Conv2 same: } 112\times112\times40. \quad \text{Pool2: } 56\times56\times40. \] \[ \text{Flatten: } 56\times56\times40 = 125{,}440. \]

Conv1 parameters

Each filter \(5\times5\times3 = 75\) weights + 1 bias \(= 76.\) 20 filters:

\[ P_{Conv1}=76\times20 \quad \boxed{P_{Conv1}=1{,}520} \]

Pool1

\[ \boxed{P_{Pool1}=0} \]

Conv2 parameters

Input has 20 channels, not 3. Each \(7\times7\) filter: \(7\times7\times20 = 980\) weights + bias \(= 981.\) 40 filters:

\[ P_{Conv2}=981\times40. \quad \boxed{P_{Conv2}=39{,}240} \]

This channel-count transition is exactly the sort of thing that can cause errors in the exam.

Pool2

\[ \boxed{0} \]

FC1 parameters

\[ P_{FC1} = 125{,}440\times100+100 = 12{,}544{,}000+100 \]
\[ \boxed{P_{FC1}=12{,}544{,}100} \]

Notice how enormous this is compared with the convolution layers.

FC2 parameters

\[ 100\times5+5 \quad \boxed{P_{FC2}=505} \]

Total

\[ P_{total} = 1520+39{,}240+12{,}544{,}100+505 \quad \boxed{ P_{total}=12{,}585{,}365 } \]
