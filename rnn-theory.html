1. Why feed-forward networks are unsuitable for sequential data

fundamentals
QuestionWhy are ordinary feed-forward neural networks unsuitable for sequential data?

Sequential data have an important temporal order, and the current prediction may depend on information that appeared earlier in the sequence — language, speech, video, time series, sensor signals.

A feed-forward network processes each input independently and maintains no internal state across time. It therefore cannot remember previous inputs or model temporal dependencies. An RNN solves this by introducing a hidden state that carries information from previous time steps forward.

  feed-forward                     recurrent

  x₁ ──► [net] ──► y₁              x₁ ──► [net] ──► y₁
  x₂ ──► [net] ──► y₂                      │ h₁
  x₃ ──► [net] ──► y₃              x₂ ──► [net] ──► y₂
                                            │ h₂
  no link between steps            x₃ ──► [net] ──► y₃
  each input seen in isolation              state carried forward

A second, more practical problem: a feed-forward network has a fixed input size, so it cannot handle sequences of varying length without padding or truncation. An RNN reuses the same cell at every step, so length is not baked into the architecture.

2. What an RNN is, and the role of the hidden state

fundamentals
QuestionWhat is a Recurrent Neural Network? Explain the role of the hidden state.

An RNN is designed for sequential data. At each time step it combines the current input \(x_t\) with the previous hidden state \(h_{t-1}\):

\[ \boxed{ h_t=\phi\big(W_h h_{t-1}+W_x x_t+b\big) } \]

The hidden state \(h_t\) acts as the network's memory, carrying information from earlier time steps forward through the sequence.

Parameter sharing

An important property is that the same computation and the same parameters are reused at every time step. The matrices \(W_h, W_x\) and bias \(b\) do not change with \(t\).

   unrolled through time — note the SAME W at every step

        h₀        h₁        h₂        h₃
         │         │         │         │
    ┌────▼────┐┌───▼─────┐┌──▼──────┐┌─▼───────┐
    │  W, b   ││  W, b   ││  W, b   ││  W, b   │
    └────▲────┘└───▲─────┘└──▲──────┘└─▲───────┘
         │         │         │         │
        x₁        x₂        x₃        x₄

Because of this sharing, an RNN can process sequences of different lengths without needing a separate network for every position, and a pattern learned at one position transfers to all the others.

For example, sentiment analysis reads an entire sequence of words and produces one label, so it is many-to-one. Machine translation receives a sequence and generates another sequence that may have a different length, so it is many-to-many unaligned.

The distinction between aligned and unaligned matters: aligned means one output per input step, produced as you go; unaligned means the whole input is consumed first, then the output is generated — which is exactly the encoder–decoder structure of seq2seq.

4. Short-term vs long-term dependencies

the core problem
QuestionDifferentiate short-term and long-term dependencies in RNNs.

A short-term dependency occurs when the information needed for the current prediction appeared only a few steps earlier:

"I studied medicine, so I am a doctor."

The relevant information is nearby, so a vanilla RNN normally preserves it easily.

A long-term dependency occurs when the important information appeared many time steps earlier. The signal must travel through many recurrent transitions, and the gradient may gradually shrink. The network can then lose the earlier information and fail to connect distant parts of the sequence.

  short-term:   ... studied MEDICINE , so I am a ___
                          └──── 5 steps ────┘        easy

  long-term:    I grew up in FRANCE ... (40 words) ... I speak fluent ___
                             └──────── 40+ steps ────────┘   hard
\[ \boxed{ \text{The difficulty is not the distance itself — it is the number of transformations the signal must survive.} } \]

5. Why a vanilla RNN struggles with long-term dependencies

vanishing gradient
QuestionWhy does a vanilla RNN struggle with long-term dependencies?

In a standard RNN,

\[ h_t=\tanh\big(W_x x_t+W_h h_{t-1}+b\big) \]

During backpropagation through time, the gradient must pass backward through many recurrent steps. Each step contributes a factor of the recurrent weight and the activation derivative, so the gradient across \(k\) steps carries a product of \(k\) such factors.

When those factors are smaller than 1, the product shrinks geometrically:

\[ \boxed{ \text{many recurrent steps} \rightarrow \text{gradient shrinking} \rightarrow \text{loss of long-term information} } \]

This is the vanishing-gradient problem, and it makes long-term dependencies hard for vanilla RNNs to learn.

Per-step factorAfter 10 stepsAfter 50 steps
0.90.350.005
0.50.001\(\approx10^{-15}\)

Note that \(\tanh'(z)=1-\tanh^2(z)\le1\), so the activation alone can never amplify the gradient — it can only leave it unchanged at best. Combined with repeated multiplication by \(W_h\), decay is the default outcome. The mirror-image failure, exploding gradients, occurs when the factors exceed 1.

6. Vanilla RNN vs LSTM

LSTM
QuestionCompare a vanilla RNN and an LSTM.

A vanilla RNN has one hidden state and a simple repeating module, commonly based on tanh:

\[ h_t=\tanh\big(W_x x_t+W_h h_{t-1}+b\big) \]

Its hidden state must simultaneously store long-term memory and produce the current representation — two competing jobs in one vector, which is why long-term information is hard to preserve.

An LSTM introduces a separate cell state \(C_t\) for long-term memory, together with forget, input and output gates. Its memory is updated additively rather than being overwritten at each step, so gradients and information travel more stably across long sequences.

Vanilla RNNLSTM
State\(h_t\) only\(h_t\) and \(C_t\)
Updateoverwritten each stepadditive, gated
Gatesnoneforget, input, output
Long-term memoryweakexplicit
\[ \boxed{ \text{RNN: simple but weak long-term memory} } \] \[ \boxed{ \text{LSTM: gated cell state for long-term memory} } \]

7. Peephole connections

LSTM variant
QuestionWhat is a peephole LSTM connection? Why can it be useful?

In a standard LSTM, the gates make their decisions using only the current input \(x_t\) and the previous hidden state \(h_{t-1}\).

A peephole connection additionally lets the gates observe the cell state directly. For example:

\[ f_t=\sigma\big(W_f[\,C_{t-1},\,h_{t-1},\,x_t\,]+b_f\big) \]

and similarly for the input gate. The output gate can also observe the current cell state \(C_t\).

  standard gate                  gate with peephole

   h(t-1) ┐                       h(t-1) ┐
          ├──► [ σ ] ──► f_t             ├──► [ σ ] ──► f_t
     x_t ─┘                         x_t ─┤
                                  C(t-1) ┘   ← the extra "peephole"
   decides without seeing          decides while seeing
   what memory holds               what memory already holds

The intuition is that a gate can make a better decision when it directly knows what is already stored in memory — it has extra context for deciding what to forget, add or expose.

8. Coupled forget and input gates

LSTM variant
QuestionWhat are coupled forget and input gates in an LSTM?

In a standard LSTM the forget gate and input gate are independent: one controls how much old information is removed, the other how much new information is added. Nothing stops the network from erasing everything and writing nothing, or keeping everything and adding more on top.

In the coupled-gate variant, these decisions are linked:

\[ \boxed{ C_t = f_t\odot C_{t-1} + (1-f_t)\odot\tilde C_t } \]

When more old memory is retained, less new information is written; when old memory is erased, more new information replaces it.

\(f_t\)Old memory keptNew content written
1.0allnone
0.5halfhalf
0.0noneall
\[ \boxed{ \text{Forget old information and write new information jointly.} } \]

This also removes one whole gate's worth of parameters — and it is precisely the idea the GRU's update gate generalises.

9. What a GRU is, and its components

GRU
QuestionWhat is a GRU? Explain its main components.

The Gated Recurrent Unit (GRU) is a simplified gated recurrent architecture. Unlike an LSTM it has no separate cell state — the hidden state \(h_t\) itself stores the memory. It also merges the LSTM's forget and input behaviour into a single update gate.

The two gates

\[ \boxed{ z_t=\sigma\big(W_z[h_{t-1},x_t]+b_z\big) } \qquad \text{update gate} \] \[ \boxed{ r_t=\sigma\big(W_r[h_{t-1},x_t]+b_r\big) } \qquad \text{reset gate} \]

The candidate and the final state

\[ \boxed{ \tilde h_t=\tanh\big(W_h[\,r_t\odot h_{t-1},\,x_t\,]+b_h\big) } \] \[ \boxed{ h_t=(1-z_t)\odot h_{t-1} + z_t\odot\tilde h_t } \] 
   inputs:  h(t-1) , x_t
      │
      ├──► [ σ ] ──► r_t                        reset gate
      ├──► [ σ ] ──► z_t                        update gate
      │
      └──► tanh( W_h [ r_t ⊙ h(t-1) , x_t ] ) ──► h̃_t      candidate

   h_t  =  (1 − z_t) ⊙ h(t-1)   +   z_t ⊙ h̃_t
           └──── keep old ────┘      └── write new ──┘
                        the two shares always sum to 1

Note the structural echo of the coupled-gate LSTM in question 8: one gate decides both how much to keep and how much to write, so the two fractions necessarily sum to 1.

10. Roles of the update gate and reset gate

GRU
QuestionExplain the roles of the update gate and reset gate in a GRU.

Update gate \(z_t\)

Determines how much of the previous hidden state is retained and how much is replaced by the newly computed candidate:

\[ h_t=(1-z_t)h_{t-1}+z_t\tilde h_t \]

A small \(z_t\) preserves more old information; a large \(z_t\) lets more new information into the hidden state.

Reset gate \(r_t\)

Controls how much of the previous hidden state is used when computing the candidate:

\[ \tilde h_t=\tanh\big(W_h[\,r_t\odot h_{t-1},\,x_t\,]+b_h\big) \]

A small reset value reduces the influence of past information, letting the GRU effectively "reset" some of its previous memory and build a candidate largely from the current input.

GateActs onQuestion it answers
Update \(z_t\)the final mix of old and newhow much should I change?
Reset \(r_t\)the candidate's view of the pasthow much of the past is relevant right now?

The distinction that earns the mark: the reset gate acts before the candidate is formed, the update gate acts after. They operate at different points in the computation, not on the same quantity.

11. LSTM vs GRU

GRU
QuestionCompare LSTM and GRU.
LSTMGRU
Separate hidden state \(h_t\) and cell state \(C_t\)Only hidden state \(h_t\)
Forget, input and output gatesUpdate and reset gates
More complexSimpler
More parametersFewer parameters
Explicit long-term cell memoryHidden state itself stores memory

The GRU merges the forget/input behaviour, eliminates the separate cell state, and therefore has a simpler architecture with fewer parameters.

How many fewer?

An LSTM computes four gated quantities (\(f,i,\tilde C,o\)); a GRU computes three (\(z,r,\tilde h\)). Each is one weight-matrix-plus-bias block, so:

\[ \frac{\text{GRU parameters}}{\text{LSTM parameters}} \approx \frac{3}{4} \]

Both were designed to improve a recurrent model's ability to handle long-term dependencies; the GRU achieves it with a more compact gating structure.

12. Why the cell-state update is called additive

why gating works
QuestionWhy is the LSTM cell-state update called "additive" and why is this important?

The LSTM updates its cell state as

\[ \boxed{ C_t = f_t\odot C_{t-1} + i_t\odot\tilde C_t } \]

The previous memory is partly retained and new information is added to it, rather than the state being completely replaced.

This additive path lets information and gradients travel through many time steps with far fewer destructive transformations. Consequently LSTMs learn longer dependencies more reliably and train more stably than vanilla RNNs.

  vanilla RNN — every step is a full transformation

    h₀ ─[tanh W]→ h₁ ─[tanh W]→ h₂ ─[tanh W]→ h₃      gradient multiplied each time

  LSTM — the memory line is only scaled and added to

    C₀ ──×f──+i──► C₁ ──×f──+i──► C₂ ──×f──+i──► C₃    when f ≈ 1 the path is ≈ straight

The key contrast: in a vanilla RNN the gradient is multiplied by \(W_h\) and \(\tanh'\) at every step, so decay is automatic. In an LSTM the gradient along the cell state is multiplied by \(f_t\) — and the network can learn to set \(f_t\approx1\), keeping that product near 1 for as long as the information is needed.

13. Why gates use sigmoid

why gating works
QuestionWhy do LSTM/GRU gates use Sigmoid?

A gate needs to control how much information passes through. Sigmoid produces values in

\[ \boxed{ (0,1) } \]

so it works naturally as a soft switch:

\[ 0 \rightarrow \text{block information} \qquad 1 \rightarrow \text{allow information} \]

and values in between allow partial information flow. A gate output multiplies the signal it controls, so a range of \((0,1)\) is exactly a scaling factor between "none" and "all".

Being smooth and differentiable, sigmoid also lets these decisions be learned by gradient descent — a hard 0/1 switch would have zero gradient everywhere and could never be trained.

ComponentActivationRangeWhy
Gates \(f,i,o,z,r\)\(\sigma\)(0,1)a fraction to let through
Candidate \(\tilde C,\tilde h\)\(\tanh\)(−1,1)content, which may be negative

This is the cleanest way to remember which activation goes where: valves use sigmoid, content uses tanh.
