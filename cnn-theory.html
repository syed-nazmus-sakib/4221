1. ResNet vs DenseNet

direct previous-year theory question

ResNet

\[ \boxed{y=F(x)+x} \]

Input travels through a shortcut and is added to the transformed representation: \(x\rightarrow F(x)\) plus \(x\rightarrow\text{shortcut}\), then \(\boxed{F(x)+x}\). Deep nets suffer difficult optimization / weak gradients; the shortcut gives an easier route.

\[ \boxed{\text{Addition}} \]

DenseNet

Instead of adding, it concatenates:

\[ \boxed{ x_l=H_l([x_0,x_1,\ldots,x_{l-1}]) } \]

E.g. \(x_0\rightarrow x_1\), layer 2 receives \([x_0,x_1]\), layer 3 receives \([x_0,x_1,x_2]\), and so on.

\[ \boxed{\text{Concatenation}} \]

Exam comparison

ResNetDenseNet
Skip connectionsDense connections
Features addedFeatures concatenated
\(F(x)+x\)\([x_0,x_1,\ldots]\)
Residual reuseEvery later layer directly receives earlier features
Channels need not growConcatenation tends to increase channels

DenseNet preserves earlier features more explicitly because old maps remain separately available instead of merged by summation.

ResNet combines transformed features with input using element-wise addition, \(y=F(x)+x\). DenseNet concatenates outputs of all preceding layers; earlier maps remain explicitly available and strongly reused.

2. Standard vs Depthwise-Separable Convolution

most important concept · in-course + retake numerical core

Suppose \(C_{in}=M,\; C_{out}=N\), kernel \(K\times K\).

Standard convolution

Every output filter sees every input channel. One filter \(K\times K\times M.\) With \(N\) filters:

\[ \boxed{ K^2MN } \]

weights, ignoring biases. Spatial filtering + channel mixing simultaneously.

Depthwise convolution

One \(K\times K\) filter per input channel:

\[ \boxed{K^2M} \]

E.g. 32 channels → 32 separate spatial filters. Depth usually stays \(32\rightarrow32\).

\[ \boxed{\text{Spatial filtering}} \]

Pointwise convolution

\(1\times1\) filters, each seeing all input channels:

\[ \boxed{MN} \]
\[ \boxed{\text{Channel mixing}} \]
\[ \boxed{ \text{Depthwise = spatial processing} } \qquad \boxed{ \text{Pointwise = channel mixing} } \]

Why the saving?

\[ \text{Standard: } K^2MN. \quad \text{DS: } K^2M+MN. \] \[ \frac{K^2M+MN}{K^2MN} = \frac{K^2+N}{K^2N} = \boxed{ \frac1N+\frac1{K^2} } \]

For \(K=3,\; N=64\): \(\frac1{64}+\frac19 \approx 0.127.\) DS uses only ~\(\boxed{12.7\%}\) of standard params (biases ignored).

3. What does a \(1\times1\) convolution actually do?

At one spatial position \([x_1,\ldots,x_{32}]\), a \(1\times1\times32\) filter computes \(w_1x_1+\cdots+w_{32}x_{32}+b.\) Spatial size \(1\times1\) but operates through entire channel depth. Therefore:

\[ \boxed{\text{mix information between channels}} \qquad \boxed{\text{change the number of channels}}. \]

E.g. \(112\times112\times20\) through 40 pointwise filters → \(\boxed{112\times112\times40}\) — exactly the in-course pattern.

4. Same Padding vs Valid Padding

Valid

No padding \(p=0.\) Stride 1: \(n_{out}=n-k+1.\) E.g. \(224 \xrightarrow{5\times5} 220.\)

\[ \boxed{\text{valid convolution shrinks the spatial size}} \]

Same

Padding preserves size at \(s=1.\) E.g. \(224\times224 \rightarrow 224\times224.\)

\[ \boxed{\text{same padding preserves border dimensions at stride 1}} \]

Trap: same + stride 2 still downsamples. Retake: \(64\times64 \xrightarrow[\text{same}]{3\times3,s=2} 32\times32.\)

5. Pooling vs Strided Convolution

Pooling — e.g. 2×2 s=2

\(224\times224 \rightarrow 112\times112.\)

\[ \boxed{0\text{ trainable parameters}} \]

Strided convolution — e.g. 3×3 s=2

Simultaneously learns filters, changes channels, downsamples. Retake uses strided convs for downsampling instead of pooling.

\[ \boxed{ \text{Pooling = fixed downsampling} } \qquad \boxed{ \text{strided conv = learned filtering + downsampling} } \]

6. Why does pooling increase receptive field so quickly?

Without pooling \(3\times3 \rightarrow 3\times3\): \(3\rightarrow5\), RF \(\boxed{5\times5}.\) With \(3\times3 \rightarrow 2\times2\) Pool s=2 \(\rightarrow 3\times3\): RF \(\boxed{8\times8}.\)

Reason: effective jump. Before pool \(j=1\); after stride-2 pool \(j=2.\) One step in next map = two pixels in input, so later kernels expand RF faster.

7. Why can FC layers dominate?

Last map \(56\times56\times40\) → flatten \(125{,}440\) → 100 neurons: \(125{,}440\times100+100\) = \(\boxed{12{,}544{,}100}\) params. Meanwhile DS Conv2 block = \(200+840 = \boxed{1040}\). One FC layer dwarfs all conv layers.

8. Parameters vs MACs + memorize list

\[ \text{Params } \boxed{ K^2C_{in}C_{out} } \qquad \text{MACs } \boxed{ H_oW_oK^2C_{in}C_{out} } \]

Extra \(H_oW_o\) because kernel weights reuse at every spatial position — few weights, large compute.

Memorize if exam is tomorrow

  1. ResNet: added — \(y=F(x)+x.\)
  2. DenseNet: concatenated, reused by later layers.
  3. Standard: every filter across all input channels.
  4. Depthwise: one spatial filter per channel.
  5. Pointwise: \(1\times1\) mixes + changes channels.
  6. Same: preserves size at stride 1.
  7. Valid: no padding, shrinks.
  8. Pooling: downsamples, no params.
  9. Stride >1: downsamples.
  10. RF: grows via kernels, faster after stride/downsampling.
  11. Flatten+FC: enormous counts.
  12. Params ≠ MACs: MACs add \(H_oW_o\).
