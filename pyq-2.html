1(b) PAC learning; underfitting and overfitting

learning theory
QuestionWhy do we use PAC Learning? Define Underfitting and Overfitting.

PAC — Probably Approximately Correct learning provides a theoretical framework for asking whether a learning algorithm can learn a hypothesis that is approximately correct with high probability, using a finite amount of training data. It connects model accuracy, confidence and the required sample size.

Underfitting occurs when the model is too simple to capture the underlying relationship, resulting in high training and test error.

Overfitting occurs when the model fits the training data too closely, including its noise, producing very low training error but poor generalisation to unseen data.

\[ \text{Underfitting: } E_{train}\uparrow,\ E_{test}\uparrow \qquad \text{Overfitting: } E_{train}\downarrow,\ E_{test}\uparrow \]

1(c) Factors and trade-off for a good model

bias–variance
QuestionWhich factors and trade-off need to be considered to find a good model?

A good model should balance bias and variance. A very simple model tends to have high bias and may underfit, whereas an excessively complex model has low training error but high variance and may overfit.

Model selection should therefore consider training error, validation error, model complexity, the amount of available data, and regularisation. The aim is not simply to minimise training error, but to achieve the lowest possible generalisation error.

2(b) Can a small slack penalty C hurt training accuracy?

SVM
QuestionFor linearly separable data, can a small slack penalty \(C\) hurt the training accuracy when using a linear SVM (no kernel)? If so, explain how. If not, why not?
\[ \boxed{\text{Yes}} \]

In a soft-margin SVM, \(C\) controls the penalty for violating the margin or misclassifying training points.

If \(C\) is very small, margin violations are inexpensive. The optimiser may therefore prefer a wider margin with some training errors rather than perfectly separating data that is in fact linearly separable. A sufficiently small \(C\) can therefore reduce training accuracy.

The trade-off runs the other way too: a very large \(C\) forces a perfect fit on the training set and can produce a narrow margin that generalises poorly.

2(c)(i) Setting C by cross-validation

model selection
QuestionAssume you are given a data set and you want to train a linear SVM, but do not know the value of \(C\). Explain how you can set the value of \(C\) using cross-validation.
  1. Choose several candidate values of \(C\), usually over a logarithmic range such as \(0.01,\;0.1,\;1,\;10,\;100\).
  2. For each value, perform \(k\)-fold cross-validation: train the SVM on \(k-1\) folds and evaluate on the remaining fold, repeating until every fold has served as validation data.
  3. Calculate the average validation performance for each \(C\).
  4. Choose the \(C\) giving the best cross-validation performance.
  5. Retrain the final model on the complete training set using that \(C\).

A logarithmic grid is used because \(C\) spans orders of magnitude — the difference between \(0.01\) and \(0.1\) matters far more than between \(100\) and \(100.1\).

3(a) Advantages of convolutional over fully connected layers

CNN design
QuestionWhat are the advantages of using convolutional layers instead of fully connected ones for visual tasks?

Convolutional layers exploit the spatial structure of images. Local connectivity allows filters to learn useful patterns such as edges, textures and shapes, while weight sharing allows the same feature detector to operate at every image location.

They also require far fewer parameters than fully connected layers, reducing computation and overfitting. CNNs therefore provide parameter efficiency, translation-related feature reuse, and hierarchical feature learning.

Concretely: a fully connected layer on a \(224\times224\times3\) image needs over 150,000 weights per neuron; a \(3\times3\) convolutional filter needs 27, reused at every position.

3(b) What goes wrong with ŷ = σ(ReLU(z))?

activation design
QuestionSuppose you are solving a binary classification task of classifying images as cat vs dog. You design a CNN with a single output neuron. Let the output of this neuron be \(z\). The final output is \(\hat y=\sigma(\text{ReLU}(z))\). If you classify all inputs with a final value \(\hat y\ge0.5\) as cat images, what problem are you going to encounter?

Since \(\text{ReLU}(z)\ge0\), the input to the sigmoid can never be negative. Therefore

\[ \sigma(\text{ReLU}(z))\ \ge\ \sigma(0) = 0.5 \]

The model can never produce a probability below \(0.5\), so it cannot represent the negative class at all. With a threshold of \(0.5\), essentially every input would be classified as cat.

   z:      −3   −2   −1    0    1    2    3
   ReLU:    0    0    0    0    1    2    3
   σ(·):  0.50 0.50 0.50 0.50 0.73 0.88 0.95
          └──────────────┬────┘
          all negative z collapse to exactly 0.5

Furthermore, when \(z<0\) the ReLU derivative is zero, which also blocks gradient flow — so the network cannot even learn its way out. The correct design applies the sigmoid directly to the unrestricted output logit:

\[ \boxed{ \hat y=\sigma(z) } \]

3(c) How depthwise separable convolution builds lightweight networks

efficiency
QuestionHow does depthwise separable convolution help to build lightweight deep neural networks?

A standard convolution performs spatial filtering and channel mixing simultaneously. Depthwise separable convolution separates these into two stages:

\[ \text{Depthwise convolution} \;\rightarrow\; 1\times1 \text{ pointwise convolution} \]

The depthwise stage filters each input channel independently; the pointwise stage mixes channels. This greatly reduces both parameters and multiply-accumulate operations, enabling lightweight architectures such as MobileNet.

\[ \text{standard: } H_oW_oK^2C_{in}C_{out} \qquad \text{separable: } H_oW_oK^2C_{in} + H_oW_oC_{in}C_{out} \] \[ \frac{\text{separable}}{\text{standard}}=\frac{1}{C_{out}}+\frac{1}{K^{2}} \]

For \(K=3\) the ratio is dominated by \(1/9\), so the saving is roughly \(8\)–\(9\times\) almost regardless of layer size. Derived in full on the computational cost page.

3(d) Top-1 and Top-5 accuracy

evaluation
QuestionDefine Top-1 and Top-5 accuracy.

Top-1 accuracy is the percentage of samples for which the class with the highest predicted probability is the true class.

Top-5 accuracy is the percentage of samples for which the true class appears anywhere among the five highest-probability predictions.

\[ \boxed{ \text{Top-5 accuracy} \ \ge\ \text{Top-1 accuracy} } \]

The inequality is automatic: any sample counted correct under Top-1 is also correct under Top-5, since the top prediction is one of the top five.

A discriminative model learns only what is needed to predict \(y\) from \(x\). A generative model learns the underlying data distribution and can synthesise new samples. 4(b) How a GAN trains G and D as a minimax game

GAN
QuestionHow does a Generative Adversarial Network (GAN) jointly train generator \(G\) and discriminator \(D\) with a minimax game?

A GAN contains a generator \(G\) that converts random noise \(z\) into fake samples, and a discriminator \(D\) that tries to distinguish real samples from generated ones. They optimise opposing objectives:

\[ \boxed{ \min_G\max_D \Big[ \mathbb{E}_{x\sim p_{data}}\log D(x) + \mathbb{E}_{z\sim p_z}\log\big(1-D(G(z))\big) \Big] } \] 
   z ──► [ G ] ──► fake x̂ ──┐
                              ├──► [ D ] ──► real / fake
        real x ───────────────┘
                              
   D maximises:  correctly label real as real, fake as fake
   G minimises:  make D label its fakes as real

The discriminator is trained to assign high probability to real data and low probability to generated data, while the generator is trained to produce samples that fool the discriminator. Alternating these updates creates the adversarial minimax game.

4(c) The global minimum of the GAN minimax game

GAN theory
QuestionShow mathematically when the global minimum of the GAN minimax game occurs.

For a fixed generator distribution \(p_g\), the optimal discriminator is

\[ \boxed{ D^{*}(x)=\frac{p_{data}(x)}{p_{data}(x)+p_g(x)} } \]

Substituting this optimal discriminator back into the GAN objective gives

\[ C(G) = -\log 4 + 2\,JS\big(p_{data}\,\|\,p_g\big) \]

where \(JS\) is the Jensen–Shannon divergence. Since \(JS(p_{data}\|p_g)\ge0\) with equality only when the two distributions coincide, the minimum occurs at

\[ \boxed{ p_g = p_{data} } \qquad\Longrightarrow\qquad C(G)=-\log 4, \qquad \boxed{ D^{*}(x)=\tfrac12 } \]

The global optimum is therefore achieved when the generator perfectly reproduces the real data distribution — at which point the discriminator can do no better than guessing.

5(a) How LSTM solves the vanishing-gradient problem

LSTM
QuestionHow does Long Short-Term Memory (LSTM) solve the vanishing-gradient problem?

LSTM introduces a cell state that provides a nearly linear path through time. Instead of repeatedly transforming all information through ordinary nonlinear recurrent activations, information travels along the cell state with only controlled, additive modifications:

\[ C_t = f_t\odot C_{t-1} + i_t\odot\tilde C_t \]

The forget, input and output gates determine what should be removed, added and exposed. Because the update is additive rather than a repeated matrix multiplication through a squashing nonlinearity, gradients can propagate over long time intervals, reducing the vanishing-gradient problem found in ordinary RNNs.

Contrast with a plain RNN, where the gradient through \(T\) steps carries a factor \(\prod W^T f'\) — a product that shrinks geometrically. The LSTM cell state lets that product stay near 1 when \(f_t\approx1\). Worked numerically on the lstm-1 page.

5(b) Evaluating an object detector

detection metrics
QuestionHow can we evaluate the performance of an object detector?

Detection is evaluated on both classification correctness and localisation quality.

A predicted box is counted as a true positive if it predicts the correct class and its intersection-over-union with the ground truth exceeds a chosen threshold:

\[ IoU=\frac{\text{Intersection}}{\text{Union}} \]

From true positives, false positives and false negatives, precision–recall curves are constructed. Average Precision (AP) summarises performance for one class as the area under that curve, and mean Average Precision (mAP) averages AP across classes, often at one or several IoU thresholds.

5(c) Cut weights, units, or connections to reduce backprop cost?

efficiency
QuestionSuppose you want to redesign the AlexNet architecture to reduce the number of arithmetic operations required for each backprop update. Would you try to cut down on the number of weights, units, or connections? Justify your answer.
\[ \boxed{ \text{Connections / computations} } \]

Every active connection requires arithmetic during both the forward and the backward pass, so the number of connections is what the cost is actually proportional to.

Reducing only the number of unique weights does not reduce computation proportionally, because convolutional weights are shared and reused at many spatial locations — the same 27 numbers may be applied 50,000 times. Cutting feature-map sizes, channels, or expensive layer connections directly reduces the number of multiply-accumulate operations.

This is the parameters-vs-MACs distinction: a \(3\times3\times3\times16\) layer holds 448 parameters but performs 442,368 MACs on a \(32\times32\) input. See computational cost.

5(d) Why multiple filter sizes in Inception

Inception
QuestionWhy do we use multiple filters of varying sizes in the Inception network?

Different filter sizes capture features at different spatial scales. A \(1\times1\) filter performs local channel mixing at a single position, while \(3\times3\) and \(5\times5\) filters capture progressively larger spatial structures.

Inception performs these operations in parallel and concatenates their outputs along the channel dimension, so the network can learn both fine and coarse features without committing to a single receptive-field size. The relative importance of each scale becomes something training learns, rather than a hyperparameter someone must guess.

6(b) R-CNN’s disadvantage; how Fast and Faster R-CNN fix it

detectors
QuestionWhat is the primary disadvantage of Region-based CNN (R-CNN)? How do Fast R-CNN and Faster R-CNN solve that problem?

The major disadvantage of R-CNN is its very high computational cost. It generates many region proposals and runs the CNN separately on every proposal, so overlapping regions are re-processed again and again. Both training and inference are extremely slow.

Fast R-CNN computes the convolutional feature map once for the whole image, then extracts each region's features from that shared map using ROI pooling.

Faster R-CNN goes further by replacing the external region-proposal method with a trainable Region Proposal Network (RPN) that shares convolutional features with the detector.

ModelCNN runsProposals from
R-CNNonce per proposalexternal (selective search)
Fast R-CNNonce per imageexternal (selective search)
Faster R-CNNonce per imagelearned RPN, shares features

Read the table downwards: each version removes one source of repeated work.

6(c) Solving overlapping detections

NMS
QuestionWhat approach is used to solve overlapping detections by object detectors?

The standard approach is Non-Max Suppression (NMS).

  1. Remove low-confidence boxes.
  2. Select the highest-confidence remaining box.
  3. Keep it as a prediction.
  4. Compute its IoU with the other boxes.
  5. Suppress boxes whose IoU exceeds the chosen threshold.
  6. Repeat until no boxes remain.

NMS therefore removes multiple overlapping predictions that correspond to the same object. With several classes it is run independently per class, so a car box never suppresses a person box.

7(a) Gradient descent; cost function vs gradient descent

optimisation
QuestionWhat is the concept behind Gradient Descent? What is the difference between Cost Function vs Gradient Descent?

A cost function measures how poorly the model is performing. For parameters \(\theta\) it is written \(J(\theta)\).

Gradient descent is the optimisation algorithm used to minimise that cost, by repeatedly stepping in the direction of steepest decrease:

\[ \boxed{ \theta \leftarrow \theta - \alpha\nabla_\theta J } \]
\[ \text{Cost function} = \textbf{what} \text{ should be minimised} \] \[ \text{Gradient descent} = \textbf{how} \text{ the parameters are changed to minimise it} \]

They are different kinds of object entirely — one is a function being measured, the other is a procedure being run. You could minimise the same cost function with a different optimiser, or run gradient descent on a different cost.

7(b) L1 vs L2 regularisation

regularisation
QuestionWhat are the differences between L1 and L2 regularization techniques?

L1 regularisation adds \(\lambda\sum_i|w_i|\) to the loss. It tends to drive some weights exactly to zero and therefore produces sparse models.

L2 regularisation adds \(\lambda\sum_i w_i^{2}\). It smoothly shrinks large weights toward zero but usually does not make them exactly zero.

L1L2
Penalty\(\lambda\sum|w_i|\)\(\lambda\sum w_i^{2}\)
Effect on weightsdrives some exactly to 0shrinks all smoothly
Resultsparse modelsmall, spread-out weights
Side benefitimplicit feature selectionsmoother, more stable model

The reason L1 reaches exactly zero: its gradient is a constant \(\pm\lambda\) regardless of how small \(w\) becomes, so it keeps pushing. L2's gradient is \(2\lambda w\), which vanishes as \(w\to0\) — so it never quite arrives.
